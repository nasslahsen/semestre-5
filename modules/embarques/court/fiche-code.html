L'évaluation demande d'écrire les fonctions d'un objet connecté en MQTT : une fonction de traitement, le callback et la loop. Tout le code ci-dessous vient des deux programmes MQTT du cours (le lab 6 avec la LED et la température, le lab 4 avec ThingSpeak), sauf ce qui est marqué « exemple ajouté ». Lis d'abord les trois fonctions, puis le squelette, puis teste-toi en bas de page.

Le squelette complet, à réécrire de mémoire

Le programme du lab 6, sans les affichages sur le port série. Les numéros sont les sept étapes du cours.

// 1. Bibliothèques
#include <WiFi.h>
#include <PubSubClient.h>

// 2. Paramètres : Wi-Fi, serveur MQTT
const char* ssid = "TON_WIFI";
const char* password = "TON_MOT_DE_PASSE";
const char* mqtt_server = "test.mosquitto.org";

// 3. Objets
WiFiClient espClient;
PubSubClient client(espClient);

long lastMsg = 0;
float temp = 0;
const int ledPin = 2;

void setup_wifi() {
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
  }
}

// 5. Callback : lecture du message et décision
void callback(char* topic, byte* message, unsigned int length) {
  String messageTemp;
  for (int i = 0; i < length; i++) {
    messageTemp += (char)message[i];
  }
  if (String(topic) == "ensam/gbm/light") {
    if (messageTemp == "on") {
      digitalWrite(ledPin, HIGH);
    }
    else if (messageTemp == "off") {
      digitalWrite(ledPin, LOW);
    }
  }
}

// 6. Reconnexion
void reconnect() {
  while (!client.connected()) {
    if (client.connect("ESP8266Client")) {
      client.subscribe("ensam/gbm/light");
    } else {
      delay(5000);
    }
  }
}

// 4. Setup
void setup() {
  Serial.begin(115200);
  setup_wifi();
  client.setServer(mqtt_server, 1883);
  client.setCallback(callback);
  pinMode(ledPin, OUTPUT);
}

// 7. Loop : reconnexion, acquisition, publication
void loop() {
  if (!client.connected()) {
    reconnect();
  }
  client.loop();
  long now = millis();
  if (now - lastMsg > 2000) {
    lastMsg = now;
    temp = 1.5 * analogRead(A0) / 600;
    char tempString[8];
    dtostrf(temp, 1, 2, tempString);
    client.publish("ensam/gbm/temperature", tempString);
  }
}

Le moyen de le retenir : qui je suis (bibliothèques, paramètres, objets), je prépare (setup), j'écoute (callback), je me rattrape (reconnect), je travaille (loop).

Le callback

La bibliothèque PubSubClient l'appelle toute seule, depuis client.loop(), chaque fois qu'un message arrive sur un topic auquel on est abonné. Sa première ligne est imposée : seuls les noms peuvent changer.

LignePourquoi
char* topicle topic du message reçu, en texte C
byte* message, unsigned int lengthle message en octets et son nombre d'octets : ce n'est pas une chaîne, il n'y a pas de fin de texte
String messageTemp;une chaîne vide pour reconstruire le message
for (int i = 0; i < length; i++)un tour par octet
messageTemp += (char)message[i];chaque octet devient un caractère, ajouté à la fin
if (String(topic) == "…")String(…) obligatoire : deux char* ne se comparent pas avec ==
if (messageTemp == "on")la décision : une action par message attendu

Pour qu'il soit appelé, il faut trois choses : client.setCallback(callback) dans setup(), client.subscribe("…") dans reconnect(), et client.loop() dans loop().

La version ThingSpeak du cours (lab 4) : mêmes paramètres, autres noms.

void mqttSubscriptionCallback(char* topic, byte* payload, unsigned int length) {
  Serial.print("Message arrived [");
  Serial.print(topic);
  Serial.print("] ");
  for (int i = 0; i < length; i++) {
    Serial.print((char)payload[i]);
  }
  Serial.println();
}

Ce callback ne décide rien : il affiche seulement le message. Dans setup() : mqttClient.setCallback(mqttSubscriptionCallback);.

La fonction de traitement

Elle transforme une mesure brute en valeur utile ou en décision. Elle reçoit ce qu'il faut en paramètres, calcule, et rend le résultat avec return. Le type devant le nom est le type du résultat : float pour un nombre à virgule, int pour un entier, bool pour oui ou non.

Le traitement du cours est dans la loop du lab 6 : temp = 1.5 * analogRead(A0) / 600;. Mis en fonction, il donne :

float temperature(int code) {
  return 1.5 * code / 600;
}
// dans loop() :  temp = temperature(analogRead(A0));

int zoneMax(float v[], int n) {
  int k = 0;

Où la ranger : avant callback et loop dans le fichier, pour qu'elle soit connue quand on l'appelle.

Le piège : 3.3 * code / 4095 marche, mais code / 4095 * 3.3 donne presque toujours 0, car code / 4095 est une division d'entiers. Mettre un .0 (4095.0) règle le problème.

La loop

void loop() {
  if (!client.connected()) {         // 1. reconnexion
    reconnect();
  }
  client.loop();                     // 2. écoute : appelle le callback
  long now = millis();
  if (now - lastMsg > 2000) {        // 3. toutes les 2 s
    lastMsg = now;
    float v = tension(analogRead(34));      // acquisition + traitement
    char vString[8];
    dtostrf(v, 1, 2, vString);              // nombre en texte
    client.publish("mon/topic", vString);   // publication
  }
}

Pourquoi millis() et pas delay(2000) : pendant un delay, client.loop() ne tourne pas. Les messages reçus attendent et la connexion peut tomber.

La loop du lab 4 (ThingSpeak) a les mêmes trois temps. Elle vérifie aussi le Wi-Fi, se réabonne dans la loop et publie un texte construit avec String :

Le C qu'il faut

  • Types : int (entier), long (grand entier, pour millis()), float (à virgule), bool (true, false), char* (texte C), String (texte Arduino), char t[8] (tableau de 8 caractères).
  • Variable globale : déclarée en haut, hors de toute fonction ; le callback et la loop la partagent (bool mesure, long lastMsg).
  • Constante : const int ledPin = 2;
  • Tableau : int capteurs[4] = {36, 39, 34, 35};, indices de 0 à 3.
  • Boucle : for (int i = 0; i < n; i++) { … }
  • Test : if (…) { … } else if (…) { … } else { … }
  • = donne une valeur, == compare. && : et. || : ou. ! : non.
  • Une fonction qui ne rend rien commence par void ; les autres finissent par return.
  • Chaque instruction finit par ;, chaque { a sa }.

5. Questions éclair.

Qui appelle le callback ?

client.loop(), quand un message arrive sur un topic abonné.

Pourquoi s'abonner dans reconnect() et pas dans setup() ?

Après une coupure, la reconnexion efface les abonnements : il faut se réabonner à chaque connexion.

Pourquoi dtostrf avant publish ?

publish n'envoie que du texte : le nombre doit d'abord être écrit en caractères.

Que vaut analogRead pour 3,3 V ? Pour 0 V ?

4095 pour 3,3 V.

0 pour 0 V.

Deux cartes avec le même ID sur le broker : que se passe-t-il ?

Elles se déconnectent l'une l'autre en boucle : chaque ID doit être unique.

Quel port pour MQTT, et où l'écrit-on ?

1883, dans client.setServer(mqtt_server, 1883).
