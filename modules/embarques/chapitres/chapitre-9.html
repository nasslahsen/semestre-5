Installer les outils

Installer Node.js, Node-RED, le dashboard et Mosquitto

Avant de câbler un flux, il te faut trois outils sur ton PC : Node.js, Node-RED (avec son dashboard) et le serveur MQTT Mosquitto. Liste du cours : Nodejs, Mosquitto Server, Arduino JSON Library, Proteus, Arduino IDE.

Étape 1 : installer Node.js

Télécharge Node.js pour ton système : nodejs.org/en/download. Lance l'installateur, clique sur Run, puis Next jusqu'au bout.

Le dossier de Node.js contient deux programmes : node et npm (node package manager). L'installateur ajoute ce dossier au PATH du système ; s'il ne le fait pas, ajoute-le à la main (le cours le demande).

Ouvre une nouvelle invite de commandes (Windows : touche Windows, tape cmd) et vérifie les versions :

node -v
npm -v

Tu dois voir : deux numéros de version, par exemple v22.x et 10.x (le cours montre v13.14.0 et 6.14.4 : une version plus récente marche aussi).

Étape 2 : installer Node-RED

Node-RED s'installe avec npm, la commande qui vient avec Node.js. Sous Windows, sans sudo :

npm install -g --unsafe-perm node-red

Sous macOS ou Linux, la même commande précédée de sudo :

sudo npm install -g --unsafe-perm node-red

Tu dois voir : la fin de l'installation, avec une ligne added … packages.

Étape 3 : lancer Node-RED

node-red

Ouvre ensuite l'éditeur dans le navigateur, à l'adresse http://localhost:1880 (ou http://127.0.0.1:1880).

Tu dois voir : dans la fenêtre de commande, Server now running at http://127.0.0.1:1880/ ; dans le navigateur, l'éditeur avec la palette des nœuds à gauche.

Pour arrêter Node-RED : Ctrl + C dans cette fenêtre. Pour le relancer : node-red.

Étape 4 : installer le dashboard

Dans l'éditeur : menu ≡ en haut à droite, Manage palette, onglet Install, cherche node-red-dashboard et clique sur Install. Ou bien, dans le dossier utilisateur de Node-RED (en général ~/.node-red) :

cd ~/.node-red
npm i node-red-dashboard

Redémarre Node-RED (Ctrl + C, puis node-red).

Tu dois voir : une catégorie dashboard dans la palette (button, gauge, chart…) et un onglet dashboard dans le panneau de droite. L'interface s'ouvrira à http://localhost:1880/ui.

node-red-dashboard est le dashboard du cours. Node-RED le signale comme ancien (il propose aussi Dashboard 2.0), mais il s'installe et fonctionne toujours : garde celui du cours pour suivre le lab.

Étape 5 : installer Mosquitto

Télécharge le serveur MQTT Mosquitto : mosquitto.org/download. Sous Windows, prends l'installateur 64 bits (mosquitto-…-install-windows-x64.exe) et installe-le dans C:\Program Files\mosquitto.

Regarde ce qu'il contient :

cd "C:\Program Files\mosquitto"
dir *.exe

Tu dois voir : mosquitto.exe (le broker), mosquitto_pub.exe (publier), mosquitto_sub.exe (s'abonner), mosquitto_passwd.exe et mosquitto_ctrl.exe.

L'installateur crée en général un service Windows, « Mosquitto Broker », qui tourne déjà. S'il ne tourne pas, lance le broker toi-même dans ce dossier et laisse la fenêtre ouverte :

mosquitto -v

Tu dois voir : une ligne qui dit que le broker écoute sur le port 1883 (Opening ipv4 listen socket on port 1883). Si la commande répond que le port est déjà pris, c'est que le service tourne : tout va bien.

Un premier flux MQTT

Un premier flux MQTT : sensors/voltage

Node-RED publie une tension sur le topic sensors/voltage et la reçoit aussitôt, en passant par le broker Mosquitto. C'est le premier aller-retour du lab (partie 2 du cours, MQTT communication on Node-RED and Mosquitto server).

Étape 1 : préparer

Vérifie que Mosquitto tourne (service ou mosquitto -v), lance node-red, puis ouvre http://127.0.0.1:1880.

Étape 2 : construire le flux

Le flux du cours a deux lignes. Les nœuds sont dans les catégories common et network de la palette.

  1. Glisse un nœud inject (common). Double-clique : msg.payload de type number, valeur 25. Done.
  2. Glisse un nœud mqtt out (network) et relie la sortie de inject à son entrée. Double-clique : Topic sensors/voltage ; laisse QoS et Retain vides.
  3. À côté de Server, clique sur le crayon pour créer le broker. Onglet Connection : Server 127.0.0.1, Port 1883, Protocol MQTT V3.1.1, Client ID vide, Keep Alive 60, Use clean session coché. Update, puis Done.
  4. Dessous, glisse un nœud mqtt in : Server le même broker, Topic sensors/voltage. Done.
  5. Glisse un nœud debug, nomme-le Circuit_V1, et relie mqtt in à debug.

Tu dois voir : deux lignes : inject → sensors/voltage, et sensors/voltage → Circuit_V1.

Étape 3 : déployer et tester avec le bouton

Clique sur Deploy (en haut à droite). Ouvre le panneau debug (icône d'insecte, à droite). Clique sur le petit carré à gauche du nœud inject.

Tu dois voir : sous les deux nœuds MQTT, un point vert « connected » ; dans le panneau debug : sensors/voltage : msg.payload : number puis 25.

Si les nœuds MQTT restent sur « connecting », le broker ne tourne pas : relance Mosquitto (étape 5 de l'installation).

Étape 4 : publier depuis la ligne de commande

Ouvre une deuxième invite de commandes, place-toi dans le dossier de Mosquitto, et publie une valeur sur le même topic :

cd "C:\Program Files\mosquitto"
mosquitto_pub -h localhost -t sensors/voltage -m 30

Tu dois voir : dans le panneau debug de Node-RED, "30" (une chaîne, puisqu'elle vient du texte de la commande).

Sans -t devant le topic, Mosquitto répond Error: Unknown option 'sensors/voltage', comme dans la capture du cours : -h donne le broker, -t le topic, -m le message.

Étape 5 : s'abonner depuis la ligne de commande

mosquitto_sub -h localhost -t sensors/voltage

Laisse cette fenêtre ouverte, puis clique à nouveau sur le bouton du nœud inject dans Node-RED.

Tu dois voir : 25 s'affiche dans la fenêtre de mosquitto_sub à chaque clic. Le broker distribue le message à tous les abonnés : Node-RED et la ligne de commande.

Power meter : MQTT et JSON

Power meter : MQTT et format JSON

Un compteur envoie sa tension et son courant dans un seul message JSON, {"V": 220, "I": 20}. Node-RED doit le découper et calculer la puissance (partie 3 du cours, Power meter).

Étape 1 : recevoir le message brut

Le format JSON : des paires clé-valeur entre accolades, {"key1": "value1", "key2": "value2"}. Exemple du cours : {"V": 220, "I": 20}.

  1. Glisse un nœud mqtt in : le broker 127.0.0.1:1883 de la partie précédente, Topic sensors, QoS 2, Output « auto-detect (string or buffer) ». Done.
  2. Relie-le à un nœud debug, puis Deploy.

Publie le message JSON depuis la ligne de commande. Sous Windows, les guillemets intérieurs s'échappent avec \ :

cd "C:\Program Files\mosquitto"
mosquitto_pub -h localhost -t sensors -m "{\"V\":\"220\",\"I\":\"20\"}"
mosquitto_pub -h localhost -t sensors -m '{"V":"220","I":"20"}'

Tu dois voir : dans debug, sensors : msg.payload : string[20] et le texte "{"V":"220","I":"20"}" : pour l'instant, Node-RED ne voit qu'une chaîne de caractères.

Étape 2 : le nœud json

Ajoute un nœud json (catégorie parser) après mqtt in, et un deuxième debug à sa sortie. Deploy, puis renvoie la même commande.

Tu dois voir : dans le deuxième debug, msg.payload : Object avec V: "220" et I: "20". Le nœud json a transformé le texte en objet : on peut maintenant lire chaque champ.

Étape 3 : extraire chaque champ

Ajoute trois nœuds function à la sortie du nœud json. Dans chacun, onglet On Message, colle le code :

msg.payload=msg.payload.I
return msg;
msg.payload=msg.payload.V
return msg;
msg.payload=msg.payload.V*msg.payload.I;
return msg;

Relie current et voltage à un debug, power à un autre. Deploy, puis renvoie la commande.

Tu dois voir : la fenêtre de résultat du cours : la chaîne, l'objet, puis "20" (current), "220" (voltage) et 4400 (power, un nombre). JavaScript a converti les deux chaînes en nombres pour la multiplication : 220 × 20 = 4400.

Le code de la fonction power n'est pas visible dans le cours, seulement son résultat (4400) : celui-ci donne bien ce résultat.

Le dashboard

Le dashboard Node-RED

Les valeurs défilent dans le panneau debug, mais un soignant veut des cadrans et des courbes. Le dashboard affiche le power meter dans une page web, sur le PC ou sur un téléphone du même réseau.

Étape 1 : ajouter les cadrans et les courbes

Dans la palette, catégorie dashboard :

  1. Glisse trois nœuds gauge : Current (A), Voltage (V), Power (W). Relie chaque fonction (current, voltage, power) à son cadran.
  2. Glisse trois nœuds chart et relie aussi chaque fonction à sa courbe.
  3. Dans chaque cadran, Group : crée un groupe Measurement dans un onglet (tab) IoT Lab. Mets les courbes dans un deuxième groupe, Group 2.
  4. Règle Range (min, max) : par exemple 0 à 30 A, 0 à 250 V, 0 à 6000 W. Le cours garde 0 à 10, l'aiguille resterait alors collée au bout.

Pour les courbes, mieux vaut des nombres : mets Number(msg.payload.I) et Number(msg.payload.V) dans current et voltage. Le flux à importer plus bas le fait déjà.

Étape 2 : afficher le dashboard

Deploy, puis ouvre http://127.0.0.1:1880/ui. Publie quelques mesures :

cd "C:\Program Files\mosquitto"
mosquitto_pub -h localhost -t sensors -m "{\"V\":\"220\",\"I\":\"20\"}"
mosquitto_pub -h localhost -t sensors -m "{\"V\":\"230\",\"I\":\"12\"}"
mosquitto_pub -h localhost -t sensors -m "{\"V\":\"215\",\"I\":\"25\"}"

Tu dois voir : la page IoT Lab : le groupe Measurement avec les cadrans (Power 4400 W, puis 2760, puis 5375) et le groupe 2 avec les courbes qui suivent chaque message.

Étape 3 : voir le dashboard sur un autre appareil

Le dashboard est une page web servie par ton PC. Sur un téléphone ou une tablette connecté au même Wi-Fi, ouvre Ton_adresse_IP:1880/ui. Pour trouver l'adresse IP du PC :

ipconfig

Tu dois voir : par exemple 192.168.1.23:1880/ui : le même dashboard, qui bouge en même temps que celui du PC.

Si la page ne s'ouvre pas, le pare-feu de Windows bloque sans doute Node.js : autorise-le sur le réseau privé quand Windows le demande.
