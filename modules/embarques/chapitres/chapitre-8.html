Le format JSON

JSON (JavaScript Object Notation)

Le compteur du lab envoie sa tension et son courant dans un seul message. Le récepteur doit savoir sans ambiguïté quelle valeur est V et laquelle est I, que ce récepteur soit Node-RED, un ESP32 ou une page web.

Le chapitre en bref

Ce chapitre réunit les deux outils des labs : le format JSON (cette page), dans lequel voyagent les mesures, et la plateforme ThingSpeak, où on les range, en HTTP puis en MQTT. Les labs 1 à 5 les mettent en pratique.

Intuition

Un message JSON étiquette chaque valeur avec son nom : {"V": 220, "I": 20}. Le récepteur lit les étiquettes, pas des positions : on peut ajouter un champ sans tout casser, et un humain comprend le message d'un coup d'œil.

Formalisation

JSON (JavaScript Object Notation) est un format léger d'échange de données, facile à lire et à écrire pour un humain, facile à analyser et à produire pour une machine. Il repose sur deux structures : une collection de paires nom/valeur, et une liste ordonnée de valeurs. Extension des fichiers : .json.

Usages cités par le cours : les applications JavaScript (extensions de navigateur, sites web), la sérialisation et la transmission de données structurées sur une connexion réseau, surtout entre un serveur et des applications web, les services web et les API qui fournissent des données publiques. Il s'utilise avec les langages de programmation modernes.

Syntaxe :

  • les données sont des paires nom/valeur ;
  • les accolades { } contiennent les objets ; chaque nom est suivi de :, et les paires sont séparées par des virgules ;
  • les crochets [ ] contiennent les tableaux, dont les valeurs sont séparées par des virgules.
TypeDescription (cours)
Numbernombre à virgule flottante double précision, comme en JavaScript
Stringtexte Unicode entre guillemets doubles, avec échappement par barre oblique inverse
Booleantrue ou false
Arraysuite ordonnée de valeurs
Valueune chaîne, un nombre, true ou false, null…
Objectcollection non ordonnée de paires clé:valeur
Whitespacedes espaces peuvent séparer deux éléments
Nullvide

Exemple

Exemples du cours. Un capteur et ses valeurs : {"id": "01", "values": [20, 21, 22.5]}. Une liste de capteurs : un objet dont la clé "sensors" contient un tableau de trois objets ("id": "01" de type temperature, "02" pressure, "03" humidity). En JavaScript, JSON.parse transforme le texte en objet :

const txt = '{"type":"Temperature", "Value":35, "position":"Zone1"}'
const obj = JSON.parse(txt);
document.getElementById("demo").innerHTML = obj.type + ", " + obj.position;

La page affiche alors Temperature, Zone1.

Formules clés

\[ \texttt{\{ "nom": valeur, ... \}} \text{ : objet} \qquad \texttt{[ v1, v2, ... ]} \text{ : tableau} \qquad \text{noms et chaînes entre guillemets doubles} \]

ThingSpeak : channels, écrire, lire

ThingSpeak : channels, écriture et lecture

L'ESP32 du lab mesure toutes les 5 secondes. Où ranger ces valeurs pour les retrouver, les tracer et les partager avec le médecin, sans monter son propre serveur ?

Intuition

ThingSpeak est une plateforme IoT en ligne (de MathWorks). On y crée un channel, une sorte de tableau à huit colonnes (les fields). Chaque écriture ajoute une ligne, datée, et ThingSpeak trace une courbe par colonne. Pour écrire ou lire, une simple requête HTTP suffit, avec une clé qui sert de mot de passe.

Formalisation

  • Un channel a un Channel ID et jusqu'à 8 fields (champs), plus une position, un statut et la date de chaque entrée.
  • Deux clés (onglet API Keys) : la Write API Key pour écrire, la Read API Key pour lire un channel privé.
  • Écrire depuis un navigateur : une requête HTTP GET sur https://api.thingspeak.com/update?api_key=<Write API Key>&field5=70 (exemple du cours).
  • Écrire depuis l'ESP32 (bibliothèque ThingSpeak) : ThingSpeak.setField(1, val1), setField(2, val2), puis int x = ThingSpeak.writeFields(myChannelNumber, myWriteAPIKey) ; x == 200 veut dire « Channel update successful ». writeField(…) écrit un seul champ.
  • Lire : ThingSpeak.readLongField(channel, FieldNumber, myReadAPIKey), puis getLastReadStatus() qui vaut 200 si la lecture a réussi ; readMultipleFields lit tous les champs d'un coup, puis getFieldAsInt, getFieldAsString.
  • Un graphique se règle aussi dans l'URL : …/channels/<ID>/charts/1?title=Voltage&color=FF69B4&width=850&xaxis=Time.
  • Apps : MATLAB Analysis exécute du code MATLAB sur les données (lire un channel, calculer, écrire dans un autre) ; React déclenche une action (MATLAB Analysis, ThingHTTP, ThingTweet) quand les données remplissent une condition.

Exemple

Lab 1 du cours : l'ESP32 génère val1 (de 10 en 10, remis à 0 au-delà de 100) et val2 (de 20 en 20), et les écrit dans Field 1 et Field 2 toutes les 5 s. Exemple React du cours : une mesure EPF arrive dans le channel counterAcquisition ; une analyse MATLAB en tire un état (0 si EPF < 80, 1 entre 80 et 100, 2 au-delà) et l'écrit dans le channel counterState.

Formules clés

\[ \texttt{GET api.thingspeak.com/update?api\_key=CLE\&field1=v} \qquad \texttt{writeFields(...) == 200} \Rightarrow \text{écriture réussie} \qquad 8 \text{ fields par channel} \]

ThingSpeak en MQTT

ThingSpeak et MQTT

En HTTP, l'ESP32 doit ouvrir une requête à chaque envoi, et ne sait rien des nouvelles entrées du channel sans redemander. ThingSpeak a aussi un broker MQTT : on publie, et on peut s'abonner au channel.

Intuition

ThingSpeak joue le rôle de broker. Chaque channel a deux topics : un pour publier dedans, un pour être prévenu de chaque nouvelle entrée. L'accès ne passe plus par les API Keys, mais par un « device » MQTT qui a ses propres identifiants.

Formalisation

  • Broker ThingSpeak : mqtt3.thingspeak.com, port 1883.
  • Un device MQTT (menu Devices, MQTT, Add a new device) porte les identifiants du client : Client ID, Username, Password, et la liste des channels autorisés, avec Allow Publish et Allow Subscribe. Limites : 100 devices MQTT par utilisateur, 10 channels autorisés par device.
  • Le broker répond à une connexion correcte (CONNECT) par CONNACK, et à un abonnement (SUBSCRIBE) par SUBACK.
  • Publier tous les champs : topic channels/<channelID>/publish, message field1=45&field2=60&status=MQTTPUBLISH.
  • Publier un seul champ : topic channels/<channelID>/publish/fields/field1, message 89.
  • S'abonner : topic channels/<channelID>/subscribe. À chaque entrée, le broker envoie toute l'entrée en JSON : {"channel_id":…,"created_at":"…","entry_id":…,"field1":"60",…,"status":"MQTTPUBLISH"}.
  • Sur l'ESP32 (bibliothèque PubSubClient) : mqttClient.setServer(server, 1883), connect(clientID, mqttUserName, mqttPass), publish(topic, message), subscribe(topic), setCallback(…) pour traiter les messages reçus, et loop() pour garder la connexion.

Exemple

Lab 2 du cours : l'ESP32 publie field1= HR &field2= SPO2 toutes les 15 s sur channels/<ID>/publish ; HR va de 50 à 110 par pas de 5, SPO2 de 80 à 100 par pas de 2. Abonné à channels/<ID>/subscribe, il reçoit chaque entrée en retour dans son callback. Le tampon passe à 2048 octets (setBufferSize(2048)) : sinon le JSON reçu déborde et le callback n'est jamais appelé.

Formules clés

\[ \texttt{channels/ID/publish} \quad \texttt{field1=..\&field2=..} \qquad \texttt{channels/ID/publish/fields/fieldN} \qquad \texttt{channels/ID/subscribe} \rightarrow \text{JSON de l'entrée} \]
