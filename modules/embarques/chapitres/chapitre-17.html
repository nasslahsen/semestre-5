Semelle instrumentée, la programmation

Le circuit et les broches

Le TD 1 a dimensionné l'électronique de la semelle. Le TD 2 écrit le programme de l'ESP32 qui la lit : choisir un capteur, lire sa tension, retrouver sa résistance, puis enchaîner les mesures au bouton ou au rythme d'un timer. La correction est rédigée pour le site : aucun corrigé du professeur n'a été reçu.

Ce que raconte le sujet

La semelle porte 16 capteurs de force résistifs (FSR, Force Sensitive Resistor), en deux réseaux de 8. Chaque réseau a son circuit de mesure, le même que la figure 5 du TD 1 :

  • le multiplexeur NX3L4051 relie un des 8 capteurs \(Y_0\) à \(Y_7\) à sa sortie Z, selon le code écrit sur S3 S2 S1 ;
  • l'AOP, avec \(R_G\), transforme la résistance du capteur choisi en une tension \(V_A\) ;
  • le microcontrôleur, ici un ESP32, commande S1 S2 S3 par trois sorties (P1.0, P1.1, P1.2) et lit \(V_A\) sur une entrée analogique (AIN1).

Le programme fait donc le chemin inverse du circuit : du nombre lu par l'ADC, il remonte à la tension, puis à la résistance, puis à la force.

Du capteur au nombre lu

Deux nombres du montage reviennent dans tout le programme :

\[V^+ = V_{DD}\,\frac{R_B}{R_A + R_B}\] \[V^+ = 3{,}3 \times \frac{10}{120}\] \[V^+ = 0{,}275\ \text{V}\]
  • sans appui, \(R_{FSR}\) est énorme : \(V_A\) reste à 0,275 V, soit le code \(0{,}275 \times 4095 / 3{,}3 \approx 341\) ;
  • à très forte charge, \(R_{FSR}\) tend vers \(R_0 = 71\) kΩ : \(V_A \approx 0{,}275 \times (1 + 750/71) \approx 3{,}18\) V, soit le code 3946 environ.

Le code lu reste donc entre 341 et 3946 environ : il ne descend jamais à 0, et il ne sature pas.

Question 1 : les broches

On te demande. Propose les broches de l'ESP32 qui reçoivent les signaux P1.0, P1.1, P1.2 et AIN1.

D'abord : qu'est-ce qu'une broche, et que doit faire chacune ?

Une broche (GPIO, General Purpose Input Output) est une patte de la carte reliée à la puce. Le programme décide de son rôle. Une broche peut être :

  • une sortie numérique : le programme y écrit 0 V ou 3,3 V (digitalWrite), par exemple pour allumer une LED ou donner un ordre à un autre circuit ;
  • une entrée numérique : le programme y lit 0 ou 1 (digitalRead), par exemple l'état d'un bouton ;
  • une entrée analogique : le programme y mesure une tension et obtient un nombre de 0 à 4095 (analogRead). Seules les broches reliées à un ADC (le convertisseur) savent le faire.

Maintenant, regarde le circuit de la page et demande-toi, pour chaque fil qui arrive au microcontrôleur : qui parle à qui ?

Ensuite : éliminer les broches qui ne conviennent pas

La carte ESP32 DEVKIT V1 de l'annexe a 30 broches. On les élimine une catégorie à la fois, comme un entonnoir :

  • Pas des broches de signal : EN (le redémarrage), VIN, 3V3, GND (l'alimentation). Il reste les GPIO.
  • Déjà occupées sur la carte : GPIO 1 et 3 (TX0 et RX0) relient la puce au câble USB, c'est par là qu'on téléverse le programme et qu'on lit le moniteur série. GPIO 2 porte la LED bleue. Les utiliser casserait autre chose.
  • Entrées seulement : GPIO 34, 35, 36 et 39 n'ont pas de circuit de sortie. Elles peuvent mesurer, jamais écrire. Donc jamais pour S1 à S3.
  • ADC2 et Wi-Fi : l'ESP32 a deux convertisseurs, ADC1 (GPIO 32 à 39) et ADC2 (GPIO 0, 2, 4, 12 à 15, 25 à 27). Le cours le dit : les broches de l'ADC2 ne marchent plus quand le Wi-Fi est utilisé. Une semelle connectée envoie ses mesures en Wi-Fi : la mesure doit donc se faire sur l'ADC1.
  • Broches sensibles au démarrage (complément, pas dans le cours) : GPIO 0, 2, 5, 12 et 15 sont lues par la puce au démarrage pour choisir son mode. Un montage qui les force à 0 ou à 1 peut empêcher la carte de démarrer : on les évite quand on peut.
Enfin : choisir
  • Pour S1, S2, S3 (trois sorties) : il reste beaucoup de choix (4, 13, 14, 16 à 19, 21 à 23, 25 à 27, 32, 33). On prend GPIO 25, 26, 27 : trois broches voisines sur la carte, ce qui rend le câblage simple, et aucune n'est sensible au démarrage. N'importe quel trio de cette liste serait juste.
  • Pour AIN1 (une mesure, avec le Wi-Fi) : il faut l'ADC1, donc GPIO 32, 33, 34, 35, 36 ou 39. On prend GPIO 34 : elle est en entrée seulement, ce qui ne gêne pas pour une mesure, et on garde 32 et 33 (qui savent aussi être des sorties) pour autre chose.
  • Pour le second réseau de 8 capteurs : son AOP sort une autre tension, AIN2, sur une autre broche de l'ADC1, GPIO 35. Les deux multiplexeurs peuvent partager S1, S2, S3 : ils choisissent le même numéro de capteur, et l'ESP32 lit les deux tensions l'une après l'autre.

Les quatre fonctions de base

Avant d'enchaîner les mesures, il faut quatre briques : préparer les broches, choisir un capteur, lire sa tension, retrouver sa résistance. Chacune tient en quelques lignes et sert ensuite partout.

Le début du programme : les noms des broches

On donne un nom à chaque broche et à chaque valeur du montage, une fois pour toutes. Changer de broche ne demande alors de toucher qu'une ligne, et le programme se lit comme le schéma : on écrit S1 au lieu de 25.

  • const int S1 = 25; : une constante entière nommée S1, qui vaut 25 (la broche choisie à la question 1). const veut dire qu'elle ne changera jamais.
  • const float RA = 110000.0; : un réel (float), parce qu'on va faire des divisions avec des décimales. Les résistances sont en ohms : 110 kΩ = 110 000 Ω.
  • VP est calculée une seule fois au début : c'est le \(V^+ = 0{,}275\) V du montage, dont on aura besoin dans rsensor().
const int S1 = 25;            // P1.0 : bit de poids faible du multiplexeur
const int S2 = 26;            // P1.1
const int S3 = 27;            // P1.2 : bit de poids fort
const int AIN1 = 34;          // VA du premier réseau (ADC1_CH6)

const float VDD = 3.3;        // V
const float RA = 110000.0;    // ohms
const float RB = 10000.0;
const float RG = 750000.0;
const float VP = VDD * RB / (RA + RB);   // tension sur l'entrée + de l'AOP : 0,275 V

configSensors() : configurer les broches

On te demande. Configure les broches de sélection des capteurs.

Ce qu'il faut savoir.

  • pinMode(broche, OUTPUT) fait d'une GPIO une sortie, digitalWrite(broche, HIGH ou LOW) y écrit 3,3 V ou 0 V.
  • Une broche analogique n'a pas besoin de pinMode pour analogRead. On peut fixer la résolution de l'ADC avec analogReadResolution(12) : 12 bits est déjà la valeur par défaut sur l'ESP32, l'écrire rend le programme clair.

Ce que fait chaque ligne.

  • Trois pinMode(…, OUTPUT) : on annonce à la puce que S1, S2, S3 sont des sorties. Sans cette ligne, la broche reste en entrée et digitalWrite n'aurait aucun effet sur le multiplexeur.
  • analogReadResolution(12) : les mesures sont rendues sur 12 bits, de 0 à 4095.
  • selectSensor(0) : on part d'un état connu, le capteur Y0, plutôt que d'un état au hasard.

Cette fonction est appelée une seule fois, dans setup(), au démarrage.

Réponse.

void configSensors() {
  pinMode(S1, OUTPUT);
  pinMode(S2, OUTPUT);
  pinMode(S3, OUTPUT);
  analogReadResolution(12);   // codes de 0 à 4095
  selectSensor(0);            // départ sur Y0, rien n'est laissé au hasard
}

selectSensor(num) : choisir le capteur

On te demande. Sélectionne le capteur dont le numéro est donné en argument, de Y0 à Y7.

Ce qu'il faut savoir.

  • Le multiplexeur relie \(Y_k\) à Z quand S3 S2 S1 écrit \(k\) en binaire, S1 étant le bit de poids faible.
  • Le bit de rang \(i\) d'un entier se lit avec un décalage et un masque : (num >> i) & 1 vaut 0 ou 1.
num01234567
S3 S2 S1000001010011100101110111

Comment on extrait un bit, sur un exemple. Prenons num = 6, qui s'écrit 110 en binaire (4 + 2 + 0). On veut S1 = 0, S2 = 1, S3 = 1.

PourDécalage num >> iMasque & 1Résultat
S1 (bit 0)6 >> 0 = 110 (on ne décale pas)110 & 001 = 0S1 = 0
S2 (bit 1)6 >> 1 = 11 (on pousse d'un cran vers la droite, le dernier bit tombe)011 & 001 = 1S2 = 1
S3 (bit 2)6 >> 2 = 1001 & 001 = 1S3 = 1

Le décalage amène le bit qui nous intéresse tout à droite ; le masque & 1 efface tous les autres. Il reste 0 ou 1, exactement ce que digitalWrite attend (LOW ou HIGH).

Réponse.

void selectSensor(int num) {
  digitalWrite(S1, (num >> 0) & 1);   // bit 0
  digitalWrite(S2, (num >> 1) & 1);   // bit 1
  digitalWrite(S3, (num >> 2) & 1);   // bit 2
}

Exemple : selectSensor(6). 6 s'écrit 110 : S1 = 0, S2 = 1, S3 = 1, le capteur Y6 (\(R_{FSR7}\)) est relié à Z.

sensorAcquisition(num) : lire le code ADC

On te demande. Lis et renvoie la valeur numérique sur 12 bits de la tension AIN1 pour le capteur numéro num.

Ce qu'il faut savoir.

  • analogRead(broche) renvoie le code de l'ADC : \(ADC\_OUT = 4095 \times ADC\_IN / 3{,}3\ \text{V}\).
  • Après un changement de voie, \(V_A\) met un peu de temps à se stabiliser : le filtre \(R_G C_F\) demande environ \(5 R_G C_F\). Avec \(C_F = 470\) pF (la proposition du TD 1), cela fait 1,8 ms.

L'ordre compte. On choisit d'abord le capteur (le multiplexeur bascule), on attend que la tension se pose, et seulement ensuite on mesure. Mesurer avant, ce serait lire le capteur précédent.

Réponse.

int sensorAcquisition(int num) {
  selectSensor(num);
  delay(2);                    // VA se stabilise (5 RG CF = 1,8 ms)
  return analogRead(AIN1);     // code de 0 à 4095
}

Sans l'attente, la première lecture donnerait encore un peu de la tension du capteur précédent.

rsensor(val) : retrouver la résistance

On te demande. Calcule et renvoie la résistance du capteur à partir du code acquis val.

Ce qu'il faut savoir. On remonte le circuit à l'envers, en deux étapes :

  • du code à la tension : \(V_A = val \times 3{,}3 / 4095\) ;
  • de la tension à la résistance, en isolant \(R_{FSR}\) dans \(V_A = V^+ (1 + R_G / R_{FSR})\).
\[\frac{V_A}{V^+} = 1 + \frac{R_G}{R_{FSR}}\] \[R_{FSR} = \frac{R_G}{\dfrac{V_A}{V^+} - 1}\]

Comment on isole \(R_{FSR}\), ligne par ligne :

  • on part de \(V_A = V^+ (1 + R_G / R_{FSR})\) (question 12 du TD 1) ;
  • on divise les deux côtés par \(V^+\) : \(V_A / V^+ = 1 + R_G / R_{FSR}\) ;
  • on enlève 1 des deux côtés : \(V_A / V^+ - 1 = R_G / R_{FSR}\) ;
  • on retourne les deux fractions : \(R_{FSR} / R_G = 1 / (V_A / V^+ - 1)\), puis on multiplie par \(R_G\).

Si \(V_A \le V^+\), le dénominateur est nul ou négatif : aucun appui, la résistance est « infinie ». Le programme doit traiter ce cas au lieu de diviser par zéro.

Réponse.

float rsensor(int val) {
  float va = val * VDD / 4095.0;   // code -> tension (V)
  if (va <= VP) {
    return INFINITY;               // pas d'appui : résistance infinie
  }
  return RG / (va / VP - 1.0);     // résistance du capteur (ohms)
}

Attention au 4095.0 : écrit 4095, le calcul val * 3.3 / 4095 reste juste ici parce que 3.3 est déjà un réel, mais val / 4095 seul serait une division entière qui vaut 0.

Un calcul complet, du code à la force

Le capteur Y2 renvoie le code 2048.

Tension :

\[V_A = val \times \frac{3{,}3}{4095}\] \[V_A = 2048 \times \frac{3{,}3}{4095}\] \[V_A \approx 1{,}650\ \text{V}\]

Résistance :

\[R_{FSR} = \frac{R_G}{V_A / V^+ - 1}\] \[R_{FSR} = \frac{750}{1{,}650 / 0{,}275 - 1}\] \[R_{FSR} \approx 150\ \text{k}\Omega\]

Le TD ne le demande pas, mais le modèle du capteur donne aussi la force, en isolant \(F\) dans \(R_{FSR} = R_0 + \beta / F\) :

\[F = \frac{\beta}{R_{FSR} - R_0}\] \[F = \frac{629}{150 - 71}\] \[F \approx 8{,}0\ \text{N}\] 
float force(float r) {
  const float BETA = 629000.0;   // ohms x newtons
  const float R0 = 71000.0;      // ohms
  if (r <= R0) return INFINITY;  // hors du modèle
  return BETA / (r - R0);        // newtons ; 0 si r est infinie
}

À retenir

  • Choisir \(Y_k\) : écrire les bits de \(k\) sur S1 (bit 0), S2 (bit 1), S3 (bit 2).
  • Lire : sélectionner, attendre la stabilisation, puis analogRead.
  • Du code à la résistance : \(V_A = val \times 3{,}3 / 4095\), puis \(R_{FSR} = R_G / (V_A / V^+ - 1)\), en traitant \(V_A \le V^+\).

Version 1 : modes et bouton

Une mesure seule est bruitée, et la semelle a 8 capteurs par réseau. La version 1 range les mesures dans un tableau et propose trois modes : un capteur, un capteur moyenné, tout le réseau moyenné. Un bouton lance un cycle.

Le tableau des mesures

On te demande. Déclare un tableau de mesures pour 8 capteurs : 8 éléments réels.

Ce qu'il faut savoir. En C, float t[8]; réserve 8 réels, numérotés de t[0] à t[7] : les mêmes numéros que les voies Y0 à Y7. Déclaré en dehors de toute fonction, le tableau est global : acquisition() le remplit, loop() le lit.

Réponse.

const int NB_CAPTEURS = 8;
float mesures[NB_CAPTEURS];   // résistance de chaque capteur (ohms), case k = voie Yk

acquisition(mode, num, N) : les trois modes

On te demande. Écris void acquisition(int mode, int num, int N) :

  • mode 0 : une mesure du capteur num ;
  • mode 1 : la moyenne de N mesures du capteur num ;
  • mode 2 : la moyenne de N mesures de chacun des 8 capteurs du réseau.

Ce qu'il faut savoir.

  • Moyenner \(N\) mesures réduit le bruit aléatoire : les écarts positifs et négatifs se compensent. L'écart type du bruit est divisé par \(\sqrt{N}\).
  • On moyenne les codes (donc les tensions), puis on convertit une seule fois en résistance. Le bruit est sur la tension, et la relation tension-résistance n'est pas linéaire : la moyenne des résistances ne serait pas la résistance de la tension moyenne.
  • La somme de 4095 codes peut dépasser ce que tient un int 16 bits sur d'autres microcontrôleurs : un long est sûr partout (sur l'ESP32, int fait déjà 32 bits).

Comment on construit la fonction.

  • Les modes 1 et 2 font tous les deux « la moyenne de N mesures d'un capteur » : on l'écrit une seule fois, dans une petite fonction d'aide, moyenneCodes().
  • Faire une moyenne : additionner N mesures dans une variable somme (une boucle for qui tourne N fois), puis diviser par N.
  • acquisition() regarde le mode avec des if : mode 0, une mesure ; mode 1, la moyenne d'un capteur ; mode 2, une boucle sur les 8 capteurs (k de 0 à 7), qui fait la moyenne de chacun.
  • À chaque fois, le résultat est converti en résistance par rsensor() et rangé dans la case du capteur, mesures[k].

Réponse. Une fonction d'aide fait la moyenne, les trois modes l'utilisent :

float moyenneCodes(int num, int N) {
  if (N < 1) N = 1;             // au moins une mesure
  selectSensor(num);
  delay(2);                     // stabilisation, une seule fois par capteur
  long somme = 0;
  for (int i = 0; i < N; i++) {
    somme += analogRead(AIN1);
  }
  return (float)somme / N;
}
void acquisition(int mode, int num, int N) {
  if (mode == 0) {                      // une mesure du capteur num
    mesures[num] = rsensor(sensorAcquisition(num));
  }
  else if (mode == 1) {                 // moyenne de N mesures du capteur num
    mesures[num] = rsensor(moyenneCodes(num, N));
  }
  else if (mode == 2) {                 // moyenne de N mesures, pour les 8 capteurs
    for (int k = 0; k < NB_CAPTEURS; k++) {
      mesures[k] = rsensor(moyenneCodes(k, N));
    }
  }
}

Deux détails :

  • rsensor() reçoit un int dans la question 2 ; la moyenne est un réel. On écrit donc float rsensor(float val) : le calcul est le même et la moyenne garde ses décimales.
  • En mode 0 et 1, seule la case num change ; les autres gardent leur dernière valeur.

Le bouton BTN_ACQ

On te demande. Ajoute un bouton nommé BTN_ACQ qui lance un cycle d'acquisition.

Ce qu'il faut savoir.

  • Un bouton entre une broche et la masse, avec une résistance de tirage vers 3,3 V (INPUT_PULLUP) : relâché, la broche lit HIGH ; appuyé, LOW.
  • GPIO 34 à 39 n'ont pas de tirage interne : le bouton va sur une autre broche, ici GPIO 4.
  • Un contact mécanique rebondit pendant quelques millisecondes : on détecte le passage de HIGH à LOW (le front), puis on attend un peu avant de relire.

Pourquoi appuyé donne LOW. Le bouton relie la broche à la masse quand on appuie. INPUT_PULLUP branche, dans la puce, une résistance entre la broche et 3,3 V :

  • bouton relâché : aucun chemin vers la masse, la résistance tire la broche vers 3,3 V, on lit HIGH ;
  • bouton appuyé : la broche est reliée directement à la masse, on lit LOW.

Pourquoi détecter le front. loop() tourne des milliers de fois par seconde. Si on lançait une mesure à chaque tour où le bouton est LOW, un seul appui en lancerait des centaines. On garde donc l'état du tour précédent (etatPrecedent) et on ne réagit qu'au moment précis où il passe de HIGH à LOW : une mesure par appui.

Réponse.

const int BTN_ACQ = 4;          // bouton entre GPIO 4 et la masse
bool etatPrecedent = HIGH;

void setup() {
  Serial.begin(115200);
  configSensors();
  pinMode(BTN_ACQ, INPUT_PULLUP);
}

void loop() {
  bool etat = digitalRead(BTN_ACQ);
  if (etatPrecedent == HIGH && etat == LOW) {   // on vient d'appuyer
    acquisition(2, 0, 10);                        // cycle : les 8 capteurs, 10 mesures chacun
    for (int k = 0; k < NB_CAPTEURS; k++) {
      Serial.print(mesures[k] / 1000.0);          // en kilo-ohms
      Serial.print(k < NB_CAPTEURS - 1 ? "\t" : "\n");
    }
    delay(50);                                    // laisse passer les rebonds
  }
  etatPrecedent = etat;
}

Variante : une interruption sur front descendant, attachInterrupt(digitalPinToInterrupt(BTN_ACQ), appui, FALLING), dont la fonction ne fait que lever un drapeau lu dans loop(). La mesure, qui dure plusieurs millisecondes, ne se fait jamais dans l'interruption.

Durée d'un cycle en mode 2 avec \(N = 10\) : 8 attentes de 2 ms, plus 80 conversions de quelques dizaines de microsecondes chacune, soit une vingtaine de millisecondes. Le bouton répond tout de suite.

À retenir

  • Un tableau global float mesures[8], une case par voie.
  • On moyenne les codes, puis on convertit une seule fois en résistance.
  • Bouton : INPUT_PULLUP, appui = LOW, on réagit au front et on laisse passer les rebonds.

Version 2 : le timer

Avec le bouton, on mesure quand quelqu'un appuie. Pour suivre la marche, il faut mesurer à intervalle régulier, sans dépendre de la durée du reste du programme. La version 2 confie le rythme à un timer matériel : toutes les secondes, il lève un drapeau, et la boucle lit les 8 capteurs.

Le chemin du temps, de l'horloge au programme :

Question 4a : un timer de période 1 s

On te demande. Programme le timer sur une période \(T_{ACQ} = 1\) s.

Ce qu'il faut savoir.

  • timerBegin(1000000) règle le compteur à 1 MHz : il avance d'un pas toutes les 1 µs. La bibliothèque choisit le pré-diviseur : \(80\ \text{MHz} / 1\ \text{MHz} = 80\).
  • timerAlarm(timer, valeur, true, 0) déclenche l'interruption quand le compteur atteint valeur ; true active le rechargement auto, 0 veut dire « sans limite de répétitions ».
  • La fonction d'interruption porte IRAM_ATTR (elle est rangée en RAM interne, rapide) et doit être courte : elle lève un drapeau, la boucle fait le travail.
  • Une variable partagée entre l'interruption et la boucle est déclarée volatile : le compilateur la relit à chaque fois au lieu d'en garder une copie.

L'idée, avant le code. Le timer est un compteur qui avance tout seul. On lui dit : avance d'un pas par microseconde, et préviens-moi à 1 000 000 pas, puis recommence. « Prévenir », c'est appeler une fonction d'interruption, qu'on écrit nous-mêmes : elle lève un drapeau (tick = true). La boucle regarde le drapeau ; quand il est levé, elle le baisse et fait les mesures.

Ce que fait chaque instruction de l'annexe.

  • hw_timer_t *timer = NULL; : une variable qui désignera le timer (vide pour l'instant).
  • timer = timerBegin(1000000); : on démarre un timer qui compte à 1 MHz, un pas par microseconde.
  • timerAttachInterrupt(timer, &onTimer); : quand l'alarme sonnera, la puce appellera la fonction onTimer.
  • timerAlarm(timer, 1000000, true, 0); : l'alarme sonne à 1 000 000 pas ; true, le compteur repart de 0 et recommence (rechargement auto) ; 0, sans limite de répétitions.
  • portENTER_CRITICAL_ISR et portEXIT_CRITICAL_ISR : pendant ces deux lignes, rien ne peut couper l'écriture de tick.

Réponse. Le nombre de pas pour 1 s :

\[T_{tic} = \frac{1}{f_{compteur}}\] \[T_{tic} = \frac{1}{10^6\ \text{Hz}}\] \[T_{tic} = 1\ \mu\text{s}\] \[\text{alarme} = \frac{T_{ACQ}}{T_{tic}}\] \[\text{alarme} = \frac{1\ \text{s}}{1\ \mu\text{s}}\] \[\text{alarme} = 1\,000\,000\] 
hw_timer_t *timer = NULL;
volatile bool tick = false;                     // levé par l'interruption, lu par loop()
portMUX_TYPE mux = portMUX_INITIALIZER_UNLOCKED;

void IRAM_ATTR onTimer() {
  portENTER_CRITICAL_ISR(&mux);
  tick = true;
  portEXIT_CRITICAL_ISR(&mux);
}

void configTimer() {
  timer = timerBegin(1000000);                  // 1 MHz : un pas par microseconde
  timerAttachInterrupt(timer, &onTimer);
  timerAlarm(timer, 1000000, true, 0);          // 1 000 000 pas = 1 s, rechargement auto
}

Deux corrections par rapport à l'annexe, sinon le programme ne compile pas :

  • l'annexe attache &onTimer mais définit onTimer0() : les deux noms doivent être les mêmes ;
  • tick n'est pas déclaré : il faut volatile bool tick = false;.

Ces fonctions (timerBegin avec une fréquence, timerAlarm) sont celles de la version 3 du paquet ESP32 de l'Arduino IDE. Les anciennes versions écrivaient timerBegin(0, 80, true), timerAlarmWrite et timerAlarmEnable.

Question 4b : tous les capteurs à chaque cycle

On te demande. Programme l'acquisition de tous les capteurs à chaque cycle, avec la période \(T_{ACQ} = 1\) s.

Ce qu'il faut savoir.

  • La boucle regarde le drapeau ; s'il est levé, elle le baisse (dans une section critique, comme l'interruption) puis lance acquisition(2, 0, N).
  • Pourquoi pas la mesure dans l'interruption : elle attend 2 ms par capteur et appelle analogRead 80 fois, bien trop long pour une interruption, qui bloquerait le reste du système.
  • Le cycle doit finir avant la seconde suivante : une vingtaine de millisecondes pour 1 000 ms, la marge est large.

Réponse. Le programme de la version 2, en entier (les fonctions des questions 2 et 3 sont reprises telles quelles) :

// ---------- broches et montage (question 1) ----------
const int S1 = 25, S2 = 26, S3 = 27;   // P1.0, P1.1, P1.2
const int AIN1 = 34;                   // VA (ADC1_CH6)
const float VDD = 3.3, RA = 110000.0, RB = 10000.0, RG = 750000.0;
const float VP = VDD * RB / (RA + RB); // 0,275 V
const int NB_CAPTEURS = 8;
float mesures[NB_CAPTEURS];

// ---------- timer (question 4a) ----------
hw_timer_t *timer = NULL;
volatile bool tick = false;
portMUX_TYPE mux = portMUX_INITIALIZER_UNLOCKED;

void IRAM_ATTR onTimer() {
  portENTER_CRITICAL_ISR(&mux);
  tick = true;
  portEXIT_CRITICAL_ISR(&mux);
}

// ---------- fonctions de base (question 2) ----------
void selectSensor(int num) {
  digitalWrite(S1, (num >> 0) & 1);
  digitalWrite(S2, (num >> 1) & 1);
  digitalWrite(S3, (num >> 2) & 1);
}

void configSensors() {
  pinMode(S1, OUTPUT);
  pinMode(S2, OUTPUT);
  pinMode(S3, OUTPUT);
  analogReadResolution(12);
  selectSensor(0);
}

int sensorAcquisition(int num) {
  selectSensor(num);
  delay(2);
  return analogRead(AIN1);
}

float rsensor(float val) {
  float va = val * VDD / 4095.0;
  if (va <= VP) return INFINITY;
  return RG / (va / VP - 1.0);
}

// ---------- acquisition (question 3) ----------
float moyenneCodes(int num, int N) {
  if (N < 1) N = 1;
  selectSensor(num);
  delay(2);
  long somme = 0;
  for (int i = 0; i < N; i++) somme += analogRead(AIN1);
  return (float)somme / N;
}

void acquisition(int mode, int num, int N) {
  if (mode == 0) mesures[num] = rsensor(sensorAcquisition(num));
  else if (mode == 1) mesures[num] = rsensor(moyenneCodes(num, N));
  else if (mode == 2) {
    for (int k = 0; k < NB_CAPTEURS; k++) mesures[k] = rsensor(moyenneCodes(k, N));
  }
}

// ---------- programme principal (question 4b) ----------
void setup() {
  Serial.begin(115200);
  configSensors();
  timer = timerBegin(1000000);              // 1 MHz
  timerAttachInterrupt(timer, &onTimer);
  timerAlarm(timer, 1000000, true, 0);      // toutes les 1 s
}

void loop() {
  if (tick) {
    portENTER_CRITICAL(&mux);
    tick = false;                           // drapeau baissé avant de mesurer
    portEXIT_CRITICAL(&mux);

    acquisition(2, 0, 10);                  // les 8 capteurs, 10 mesures chacun
    for (int k = 0; k < NB_CAPTEURS; k++) {
      Serial.print(mesures[k] / 1000.0);    // kilo-ohms
      Serial.print(k < NB_CAPTEURS - 1 ? "\t" : "\n");
    }
  }
  // le reste du temps, la boucle est libre (Wi-Fi, envoi des données...)
}

Le moniteur série reçoit une ligne de 8 résistances par seconde, exactement. Si l'envoi Wi-Fi ralentit la boucle, la mesure suivante n'est pas décalée : c'est le timer qui donne le rythme, pas la durée de la boucle. Avec delay(1000) à la place, la période vaudrait 1 s plus la durée de tout le reste.

Pour suivre une marche, il faudrait plutôt 40 mesures par seconde et par capteur (question 13 du TD 1) : il suffit de passer l'alarme à 25 000 pas (25 ms), le reste du programme ne change pas.

À retenir

  • \(\text{alarme} = T / T_{tic}\) : 1 000 000 pas de 1 µs pour 1 s.
  • Interruption courte : elle lève un drapeau volatile, la boucle mesure.
  • Le timer donne une période exacte, indépendante de la durée de la boucle ; delay() non.
