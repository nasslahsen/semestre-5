MQTTX et ThingSpeak

Lab 1 : ThingSpeak et MQTTX

ThingSpeak a son propre broker MQTT, mqtt3.thingspeak.com, port 1883. Avant de programmer une carte, on publie et on s'abonne à la main avec MQTTX, un client MQTT pour ordinateur (tâche du cours : use MQTTX tool to send and receive data from ThingSpeak).

Étape 1 : créer le channel

Channels, New Channel. Nom MQTTChannel, Field 1 HR, Field 2 SPO2. Save. Note le Channel ID.

Tu dois voir : la page MQTTChannel avec Field 1 Chart (HR) et Field 2 Chart (SPO2).

Étape 2 : créer le device MQTT

Avec MQTT, l'accès au channel ne passe pas par les API Keys mais par un device MQTT, qui porte les identifiants du client.

  1. Menu Devices, MQTT, puis Add a new device.
  2. Name : MQTTDeviceTest.
  3. Authorize channels to access : choisis MQTTChannel, Add Channel, coche Allow Publish et Allow Subscribe.
  4. Add Device.

ThingSpeak affiche alors trois identifiants : Client ID, Username et Password. Télécharge-les (Download Credentials, en texte) et garde le fichier : le mot de passe n'est montré qu'à ce moment-là.

Tu dois voir : MQTTDeviceTest dans la liste des MQTT Devices, avec MQTTChannel et les coches publish et subscribe.

Limites notées dans le cours : 100 devices MQTT au plus par utilisateur, 10 channels autorisés au plus par device.

Étape 3 : connecter MQTTX

Installe MQTTX : mqttx.app. New Connection, puis remplis :

  • Name : ce que tu veux (le cours : myDevice2) ;
  • Client ID, Username, Password : ceux du device ;
  • Host : mqtt:// et mqtt3.thingspeak.com ; Port : 1883 ;
  • MQTT Version (dans Advanced) : 3.1, comme dans le cours.
mqtt3.thingspeak.com

Tu dois voir : après Connect, la connexion passe au vert. Côté protocole, le broker a répondu CONNACK à la demande CONNECT.

Étape 4 : publier les champs

En bas de la fenêtre, format Plaintext, QoS 0. Topic (remplace 0000000 par ton Channel ID) :

channels/0000000/publish
field1=45&field2=60&status=MQTTPUBLISH

Envoie, attends 15 s, puis envoie field1=60&field2=70&status=MQTTPUBLISH.

Tu dois voir : sur ThingSpeak, Channel Stats passe à Entries : 2, et les deux courbes ont deux points (HR de 45 à 60, SPO2 de 60 à 70).

Étape 5 : publier un seul champ

channels/0000000/publish/fields/field1
89

Tu dois voir : un nouveau point à 89 sur la courbe HR seulement.

Étape 6 : s'abonner au channel

New Subscription, topic :

channels/0000000/subscribe

QoS 0, Confirm (le broker répond SUBACK). Publie à nouveau des champs (étape 4).

Tu dois voir : un message reçu sur channels/…/subscribe, en JSON : {"channel_id":…,"created_at":"…","entry_id":…,"field1":"60","field2":"60",…,"status":"MQTTPUBLISH"}. ThingSpeak renvoie toute l'entrée à chaque abonné.

L'ESP32 publie en MQTT

Lab 2 : MQTT sur la carte ESP32

Même échange qu'avec MQTTX, mais c'est l'ESP32 qui publie HR et SPO2 toutes les 15 s sur channels/channelID/publish, et qui s'abonne à channels/channelID/subscribe pour relire chaque entrée.

Étape 1 : coller le programme du cours

Le programme des diapositives, en un seul bloc. Bibliothèque nécessaire : PubSubClient. Seuls les identifiants sont remplacés.

// Thingspeak IoT Platform: send data from ESP32 to TS Channel using MQTT
// Device (MQTTDeviceTest) defined by: mqttUserName, clientID, mqttPass
#include <PubSubClient.h>
#include <WiFi.h>
#define mqttPort 1883

// Ensure correct credentials to connect to your WiFi Network.
const char* ssid = "TON_WIFI";          // your network SSID (name)
const char* pass = "TON_MOT_DE_PASSE";  // your network password

// Ensure that the credentials here allow you to publish and subscribe to the ThingSpeak channel.
#define channelID 0000000                      // remplace par le Channel ID
const char mqttUserName[] = "TON_USERNAME";     // Username du device MQTT
const char clientID[] = "TON_CLIENT_ID";        // Client ID du device MQTT
const char mqttPass[] = "TON_PASSWORD";         // Password du device MQTT
const char* server = "mqtt3.thingspeak.com";

int status = WL_IDLE_STATUS;
long lastPublishMillis = 0;
int connectionDelay = 1;
int updateInterval = 15;
WiFiClient client;
PubSubClient mqttClient(client);
float HR = 50;
float SPO2 = 80;

// Connect to WiFi.
void connectWifi() {
  Serial.print("Connecting to Wi-Fi...");
  // Connect or reconnect to WiFi
  if (WiFi.status() != WL_CONNECTED) {
    Serial.print("Attempting to connect");
    while (WiFi.status() != WL_CONNECTED) {
      WiFi.begin(ssid, pass);
      delay(5000);
    }
    Serial.println("\nConnected.");
  }
}

// Function to handle messages from MQTT subscription.
void mqttSubscriptionCallback(char* topic, byte* payload, unsigned int length) {
  // Print the details of the message that was received to the serial monitor.
  Serial.print("Message arrived [");
  Serial.print(topic);
  Serial.print("] ");
  for (int i = 0; i < length; i++) {
    Serial.print((char)payload[i]);
  }
  Serial.println();
}

// Publish messages to a ThingSpeak channel.
void mqttPublish(long pubChannelID, String message) {
  String topicString = "channels/" + String(pubChannelID) + "/publish";
  mqttClient.publish(topicString.c_str(), message.c_str());
}

// Subscribe to ThingSpeak channel for updates.
void mqttSubscribe(long subChannelID) {
  String myTopic = "channels/" + String(subChannelID) + "/subscribe";
  mqttClient.subscribe(myTopic.c_str());
}

// Connect to MQTT server.
void mqttConnect() {
  // Loop until connected.
  while (!mqttClient.connected()) {
    // Connect to the MQTT broker.
    if (mqttClient.connect(clientID, mqttUserName, mqttPass)) {
      Serial.print("MQTT to ");
      Serial.print(server);
      Serial.print(" at port ");
      Serial.print(mqttPort);
      Serial.println(" successful.");
    } else {
      Serial.print("MQTT connection failed, rc = ");
      Serial.print(mqttClient.state());
      Serial.println(" Will try again in a few seconds");
      delay(connectionDelay * 1000);
    }
  }
}

// Initialize serial data transfer, and set the MQTT broker details in the setup method.
void setup() {
  Serial.begin(115200);
  // Delay to allow serial monitor to come up.
  delay(3000);
  // Connect to Wi-Fi network.
  connectWifi();
  // Configure the MQTT client
  mqttClient.setServer(server, mqttPort);
  // Set the MQTT message handler function.
  mqttClient.setCallback(mqttSubscriptionCallback);
  // Set the buffer to handle the returned JSON. NOTE: A buffer overflow of the message
  // buffer will result in your callback not being invoked.
  mqttClient.setBufferSize(2048);
}

// Maintain the MQTT connection, and publish data to the channel at regular time intervals in the loop method.
void loop() {
  // Reconnect to WiFi if it gets disconnected.
  if (WiFi.status() != WL_CONNECTED) {
    connectWifi();
  }
  // Connect if MQTT client is not connected and resubscribe to channel updates.
  if (!mqttClient.connected()) {
    mqttConnect();
    mqttSubscribe(channelID);
  }
  // Call the loop to maintain connection to the server.
  mqttClient.loop();
  // Update ThingSpeak channel periodically. The update results in the message to the subscriber.
  if (abs(long(millis()) - lastPublishMillis) > updateInterval * 1000) {
    mqttPublish(channelID, (String("field1=") + String(HR) + String("&field2=") + String(SPO2)));
    lastPublishMillis = millis();
    HR = 5 + HR;
    SPO2 = 2 + SPO2;
    if (HR > 110) HR = 50;
    if (SPO2 > 100) SPO2 = 80;
  }
}

Une seule différence avec les diapositives : les lignes qui font monter HR et SPO2 sont placées dans le if de publication, pour que chaque envoi monte d'un cran. Dans la diapositive, elles sont juste après l'accolade et tournent à chaque passage de loop() : les valeurs envoyées sautent alors au hasard entre 50 et 110.

Étape 2 : mettre les identifiants

  • ssid, pass : ton Wi-Fi (2,4 GHz) ;
  • channelID : l'ID de MQTTChannel ;
  • mqttUserName, clientID, mqttPass : ceux du device MQTT (lab 1). Ferme MQTTX avant : deux clients avec le même Client ID se déconnectent l'un l'autre.

Étape 3 : téléverser et regarder

Upload, Serial Monitor à 115200 bauds.

Tu dois voir : Connected., puis MQTT to mqtt3.thingspeak.com at port 1883 successful. Toutes les 15 s, une ligne Message arrived [channels/…/subscribe] {"channel_id":…,"field1":"50.00","field2":"80.00",…}, et un point de plus sur chaque courbe.

Si la carte affiche MQTT connection failed, rc = 4 ou 5, les identifiants du device sont faux ou le device n'a pas le droit sur ce channel. rc = -2 : la carte n'atteint pas le broker (Wi-Fi).

Étape 4 : lire le message reçu

Le callback mqttSubscriptionCallback affiche le topic puis le message caractère par caractère. Le tampon est porté à 2048 octets (setBufferSize) parce que l'entrée JSON renvoyée par ThingSpeak est longue : avec le tampon par défaut, le callback ne serait jamais appelé.
