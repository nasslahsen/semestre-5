Pacemaker connecté

Le sujet et les blocs

L'activité pratique du Pr A. Jbari demande de concevoir et de programmer un pacemaker embarqué et connecté, sous forme de maquette sur ESP32. Le sujet est un guide de 38 questions. Elles sont corrigées ici comme un cours : le sujet d'abord, puis chaque question avec ce qu'il faut savoir et une réponse. Beaucoup de questions demandent une proposition : la réponse donnée est une solution possible, justifiée, pas la seule.

Ce que raconte le sujet

Un pacemaker (stimulateur cardiaque, pile cardiaque) est un dispositif médical implanté qui délivre des impulsions électriques régulières au myocarde, pour déclencher les contractions à un rythme régulier. Il est implanté sous la clavicule ; il surveille l'activité cardiaque naturelle et traite les troubles du rythme.

Le projet a deux sous-systèmes :

  • SS1, instrumentation embarquée : les circuits électroniques et la programmation des fonctions de détection et de stimulation ;
  • SS2, supervision connectée : un dashboard (Node-RED, serveur web embarqué ou ThingSpeak) qui lit le mode d'activation et montre l'état du pacemaker.

Question 2 : le rôle du microprocesseur

Réponse. C'est le cerveau du pacemaker. Il :

  • exécute le programme rangé en ROM ;
  • analyse les échantillons de l'A/D et décide s'il y a eu un battement (événement détecté) ;
  • compte le temps écoulé depuis le dernier battement, avec le timer, et décide de stimuler ou non ;
  • règle l'amplitude de l'impulsion par le D/A et déclenche le générateur d'impulsions ;
  • enregistre les événements en RAM, applique les paramètres reçus par télémétrie et renvoie les données au programmateur.

Question 3 : le timer, plutôt que delay()

Ce qu'il faut savoir. Un timer est un compteur matériel qui avance au rythme d'une horloge et déclenche une interruption à l'alarme, tout seul. delay() fait attendre le processeur en tournant sur place.

Réponse. Le timer donne la base de temps : l'intervalle avant de stimuler, la période réfractaire, la largeur de l'impulsion, la cadence d'échantillonnage.

Pour un pacemaker, rater un battement pendant un delay() peut faire stimuler au mauvais moment : c'est un défaut de sécurité, pas seulement de confort.

Question 4 : le canal de détection

Réponse. Le canal de détection (Sensing Channel) écoute le cœur :

  • l'électrode au bout de la sonde capte l'activité électrique du cœur, de l'ordre de quelques millivolts ;
  • le Sensing Amplifier l'amplifie et la filtre, pour garder l'onde de dépolarisation (onde R dans le ventricule) et rejeter le bruit et les parasites ;
  • l'A/D la numérise ;
  • le microprocesseur compare le signal à un seuil de sensibilité : quand il le dépasse, c'est un événement cardiaque détecté.

Question 5 : le canal de stimulation

Réponse. Le canal de stimulation (Stimulation Channel) agit sur le cœur : sur ordre du microprocesseur, le D/A fixe l'amplitude et le générateur d'impulsions envoie une impulsion brève (quelques volts, moins d'une milliseconde) par la sonde. Le myocarde se dépolarise et se contracte : c'est un battement provoqué, quand le cœur n'en a pas fait de lui-même.

Question 6 : la boucle de rétroaction

Réponse. Le cœur, le canal de détection et le microprocesseur forment une boucle fermée :

  • le cœur bat, ou ne bat pas ;
  • le canal de détection le mesure et prévient le microprocesseur ;
  • le microprocesseur compare à ce qu'il attend : battement détecté à temps, il ne fait rien et relance son compte ; aucun battement à temps, il stimule ;
  • la stimulation fait battre le cœur, ce que le canal de détection voit à son tour.

Le pacemaker ne stimule donc que quand il le faut : il n'entre pas en compétition avec le rythme propre du patient, et il économise sa pile.

Question 7 : la télémétrie

Réponse. Le pacemaker est sous la peau : on ne peut pas le brancher. Le circuit de télémétrie (Digital I/O Interface et Coil antenna) communique sans fil, à travers le thorax, avec le programmateur du médecin :

  • lire (telemetry) : état de la pile, événements enregistrés, signal du cœur, nombre de stimulations ;
  • programmer (programming) : changer le mode, la fréquence, l'amplitude, la sensibilité, sans réopérer.

Question 11 : une impulsion périodique par timer

On te demande. Écris un programme Arduino qui génère périodiquement une impulsion de stimulation simulée avec un timer matériel.

Ce qu'il faut savoir.

  • Fréquence de stimulation et période : \(T = 60 / f\), avec \(f\) en battements par minute (bpm) et \(T\) en secondes. À 60 bpm, une impulsion par seconde.
  • Les fonctions du timer sont celles du TD 2 : timerBegin(1000000) (un pas par µs), timerAttachInterrupt, timerAlarm.
  • L'interruption ne fait que lever un drapeau ; la boucle allume la LED, puis l'éteint 20 ms plus tard sans delay(), en regardant millis().

Réponse.

const int PIN_STIM = 2;            // LED bleue de la carte
const int FREQ_BPM = 60;           // fréquence de stimulation
const int LARGEUR_MS = 20;         // durée d'allumage, visible à l'oeil

hw_timer_t *timerStim = NULL;
volatile bool impulsion = false;
unsigned long finImpulsion = 0;

void IRAM_ATTR onStim() {
  impulsion = true;                // l'interruption ne fait que lever le drapeau
}

void setup() {
  pinMode(PIN_STIM, OUTPUT);
  timerStim = timerBegin(1000000);                          // 1 pas = 1 µs
  timerAttachInterrupt(timerStim, &onStim);
  timerAlarm(timerStim, 60000000UL / FREQ_BPM, true, 0);   // 1 000 000 µs à 60 bpm
}

void loop() {
  if (impulsion) {
    impulsion = false;
    digitalWrite(PIN_STIM, HIGH);
    finImpulsion = millis() + LARGEUR_MS;
  }
  if (finImpulsion != 0 && millis() >= finImpulsion) {
    digitalWrite(PIN_STIM, LOW);
    finImpulsion = 0;
  }
}

La valeur de l'alarme : \(60 \times 10^6\ \mu\text{s} / f\). À 60 bpm, \(10^6\) pas ; à 75 bpm, 800 000 pas, soit 800 ms. Une vraie impulsion dure moins d'une milliseconde ; la LED reste allumée 20 ms pour qu'on la voie.

Question 12 : détecter un battement dans l'ECG

On te demande. Propose une méthode pour détecter un événement cardiaque dans un ECG simulé lu par l'ADC.

Ce qu'il faut savoir.

  • Sur un ECG, l'onde R (dépolarisation des ventricules) est la plus haute et la plus raide. Les ondes P et T sont plus basses et plus lentes.
  • Pour ne rater aucun pic, l'ECG est échantillonné régulièrement : 500 échantillons par seconde (une mesure toutes les 2 ms), cadencés par un timer.

Réponse. Méthode du seuil :

  • un timer lève un drapeau toutes les 2 ms ; la boucle lit alors l'ADC ;
  • on choisit un seuil au-dessus des ondes P et T et sous le sommet des ondes R (par exemple 60 % de la hauteur de l'onde R, mesurée au démarrage) ;
  • un événement est détecté au moment où le signal franchit le seuil en montant, c'est-à-dire quand l'échantillon précédent était en dessous et le courant au-dessus.

Améliorations possibles : filtrer avant (moyenne glissante sur quelques échantillons contre le bruit), ou travailler sur la pente (différence entre deux échantillons), qui fait ressortir l'onde R, très raide.

Questions 13 et 14 : l'algorithme à seuil, une seule détection par onde

On te demande. Écris un algorithme de détection à seuil, puis évite qu'une même onde soit détectée plusieurs fois.

Ce qu'il faut savoir.

  • Juste après un battement, le cœur est réfractaire : il ne peut pas en refaire un tout de suite. Le pacemaker fait pareil : pendant une période réfractaire (par exemple 250 ms), il ignore le signal.
  • Autour du seuil, le bruit fait monter et descendre le signal plusieurs fois : une hystérésis (redescendre nettement sous le seuil avant d'accepter un nouveau franchissement) évite les détections en rafale.

Réponse.

int seuil = 2500;                 // code ADC (12 bits)
const int HYSTERESIS = 200;       // il faut redescendre sous seuil - 200
int refractaire = 250;            // ms
bool auDessus = false;
unsigned long dernierEvt = 0;     // ms : instant du dernier battement

// appelée toutes les 2 ms avec le nouvel échantillon ; renvoie true si un battement commence
bool detecter(int v, unsigned long t) {
  if (t - dernierEvt < refractaire) {   // période réfractaire : on n'écoute pas
    return false;
  }
  if (!auDessus && v > seuil) {         // franchissement en montant
    auDessus = true;
    return true;
  }
  if (auDessus && v < seuil - HYSTERESIS) {
    auDessus = false;                   // le signal est bien redescendu
  }
  return false;
}

Sans période réfractaire, une onde R crochetée (deux sommets) ou bruitée compte deux battements, et la fréquence affichée double.

Question 15 : l'intervalle RR et la fréquence cardiaque

On te demande. Mesure le délai entre deux événements successifs et calcule la fréquence cardiaque à partir de l'intervalle RR.

Ce qu'il faut savoir. L'intervalle RR est le temps entre deux ondes R. Un battement toutes les RR secondes fait \(60 / RR\) battements par minute.

\[f_C = \frac{60\,000}{RR}\quad (f_C \text{ en bpm, } RR \text{ en ms})\]

Réponse. On note millis() à chaque détection ; la différence avec la détection précédente est l'intervalle RR.

unsigned long dernierR = 0;   // ms
unsigned long rr = 0;         // ms
float bpm = 0;

void battementDetecte(unsigned long t) {
  if (dernierR != 0) {
    rr = t - dernierR;
    bpm = 60000.0 / rr;
  }
  dernierR = t;
}

Exemple : deux ondes R à t = 12 400 ms et t = 13 200 ms.

\[RR = 13\,200 - 12\,400\] \[RR = 800\ \text{ms}\] \[f_C = \frac{60\,000}{800}\] \[f_C = 75\ \text{bpm}\]

Pour un affichage stable, on peut faire la moyenne des 4 à 8 derniers RR. La précision dépend de l'échantillonnage : à 2 ms près sur 800 ms, l'erreur est de 0,25 %.

Question 16 : le watchdog

On te demande. Propose une stratégie de gestion du watchdog pour détecter un blocage du programme.

Ce qu'il faut savoir. Le watchdog est un compteur que le programme doit remettre à zéro (le « nourrir ») avant la fin de son délai ; sinon, il redémarre la puce. Sur l'ESP32, le Task Watchdog (TWDT) surveille les tâches qui s'y sont inscrites.

Réponse.

  • délai de 2 s : bien plus long qu'un tour de boucle normal (quelques millisecondes), assez court pour ne pas laisser le patient longtemps sans surveillance ;
  • la remise à zéro se fait une fois par tour de loop(), là où se font la détection et la stimulation ; jamais dans une interruption de timer, qui continuerait d'arriver pendant que la boucle est bloquée ;
  • on ne nourrit le chien que si la boucle a vraiment avancé : par exemple si un échantillon a été traité depuis le dernier tour (sinon le timer d'échantillonnage est arrêté) ;
  • au redémarrage, le programme regarde la cause (esp_reset_reason()) : si c'est le watchdog, il le signale par la liaison série et repart avec des paramètres sûrs par défaut.
#include <esp_task_wdt.h>

void configWatchdog() {
  esp_task_wdt_config_t config = {
    .timeout_ms = 2000,       // 2 s sans remise à zéro : redémarrage
    .idle_core_mask = 0,      // ne pas surveiller les tâches de repos
    .trigger_panic = true     // redémarrer la puce
  };
  esp_task_wdt_reconfigure(&config);   // le paquet l'a déjà démarré : on change son réglage
  esp_task_wdt_add(NULL);              // surveiller la tâche qui exécute loop()
}

// dans loop(), une fois par tour :
//   esp_task_wdt_reset();

Si ta version du paquet ESP32 n'a pas démarré le watchdog, esp_task_wdt_init(&config) remplace esp_task_wdt_reconfigure. Le cours (chapitre 5) décrit les trois chiens de garde matériels de l'ESP32, pas ces fonctions.

À retenir

  • Maquette : ECG simulé (DAC) vers ADC1, LED pour la stimulation, timers, UART et Wi-Fi.
  • Détection : franchissement du seuil en montant, puis période réfractaire et hystérésis.
  • \(f_C = 60\,000 / RR\) avec RR en ms ; alarme du timer de stimulation : \(60 \times 10^6 / f\) µs.
  • Watchdog nourri une fois par tour de boucle, jamais dans une interruption.

La stimulation à la demande

Un pacemaker ne stimule pas à l'aveugle. Il attend un battement pendant une durée fixée ; si le cœur bat de lui-même, il ne fait rien et recommence à attendre ; sinon, il stimule. Tout l'algorithme tient dans ce compte à rebours, remis à zéro à chaque battement.

Le principe demandé

  • une impulsion de stimulation simulée part si aucun événement cardiaque n'est détecté pendant une durée prédéfinie ;
  • si un événement est détecté avant la fin de cette durée, la stimulation est inhibée ;
  • le délai de stimulation est réglable.

Cette durée s'appelle l'intervalle d'échappement : c'est la période de la fréquence la plus basse qu'on accepte. Pour une fréquence cible \(f\) en bpm :

\[T_{ech} = \frac{60\,000}{f}\quad (T_{ech} \text{ en ms})\]

Question 17 : l'organigramme

On te demande. Élabore l'organigramme de fonctionnement du circuit.

Réponse. Après l'initialisation, la boucle répète trois tests : un échantillon est-il prêt, un battement est-il détecté, l'intervalle est-il écoulé ?

Question 18 : le temps écoulé depuis le dernier battement

On te demande. Écris un algorithme qui mesure le temps écoulé depuis le dernier événement cardiaque.

Ce qu'il faut savoir. millis() donne le nombre de millisecondes depuis le démarrage, sur 32 bits non signés : il repasse à 0 au bout de 49,7 jours. Une soustraction entre deux unsigned long reste juste même après ce passage par 0.

Réponse.

dernierEvt ← millis()                     au démarrage
à chaque tour de boucle :
    ecoule ← millis() - dernierEvt
    si battement détecté :
        dernierEvt ← millis()             le compte repart de 0
    sinon si ecoule ≥ intervalle :
        stimuler
        dernierEvt ← millis()             une stimulation compte aussi comme un battement
unsigned long dernierEvt = 0;          // ms
unsigned long ecouleDepuisEvt() {
  return millis() - dernierEvt;        // juste même quand millis() repasse par 0
}

Dans le programme de la question 19, c'est le timer matériel qui fait ce compte : remettre son compteur à zéro avec timerWrite(timer, 0) revient à écrire dernierEvt = millis(), et son alarme tombe quand l'intervalle est écoulé.

Questions 19 et 20 : le programme, et la fréquence cible

On te demande. Écris un programme ESP32 qui simule cette stratégie, puis ajoute un paramètre qui règle la fréquence cardiaque cible.

Ce qu'il faut savoir.

  • Deux timers : l'un lève un drapeau toutes les 2 ms (échantillonnage), l'autre à la fin de l'intervalle d'échappement (stimulation).
  • timerWrite(timer, 0) remet le compteur d'un timer à zéro : l'alarme est repoussée d'un intervalle entier.
  • Un booléen se lit et s'écrit en une seule instruction : la section critique de l'annexe du TD 2 n'est pas indispensable pour un simple drapeau.

Réponse. Les fonctions detecter() et battementDetecte() sont celles des questions 13 à 15.

const int PIN_ECG = 34;            // ECG simulé (ADC1_CH6)
const int PIN_STIM = 2;            // LED de stimulation
const int PIN_DET = 4;             // LED « battement détecté »

int frequenceCible = 60;           // bpm (question 20)
unsigned long intervalle = 1000;   // ms : intervalle d'échappement

hw_timer_t *timerEch = NULL;       // 2 ms
hw_timer_t *timerStim = NULL;      // intervalle d'échappement
volatile bool tickEch = false;
volatile bool tickStim = false;
unsigned long finStim = 0, finDet = 0;

void IRAM_ATTR onEch()  { tickEch = true; }
void IRAM_ATTR onStim() { tickStim = true; }

void reglerFrequence(int f) {                 // question 20
  frequenceCible = f;
  intervalle = 60000UL / f;
  timerAlarm(timerStim, intervalle * 1000UL, true, 0);   // en µs
  timerWrite(timerStim, 0);                   // le nouvel intervalle part de maintenant
}

void stimuler(unsigned long t) {
  digitalWrite(PIN_STIM, HIGH);
  finStim = t + 20;                           // LED allumée 20 ms
  dernierEvt = t;                             // période réfractaire après la stimulation
  Serial.printf("S %lu\n", t);
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_STIM, OUTPUT);
  pinMode(PIN_DET, OUTPUT);
  analogReadResolution(12);
  timerEch = timerBegin(1000000);
  timerAttachInterrupt(timerEch, &onEch);
  timerAlarm(timerEch, 2000, true, 0);        // 2000 µs : 500 échantillons par seconde
  timerStim = timerBegin(1000000);
  timerAttachInterrupt(timerStim, &onStim);
  reglerFrequence(frequenceCible);
}

void loop() {
  unsigned long t = millis();
  if (tickEch) {                              // un échantillon toutes les 2 ms
    tickEch = false;
    int v = analogRead(PIN_ECG);
    if (detecter(v, t)) {                     // battement spontané : stimulation inhibée
      timerWrite(timerStim, 0);
      tickStim = false;
      dernierEvt = t;
      battementDetecte(t);                    // RR et fréquence
      digitalWrite(PIN_DET, HIGH);
      finDet = t + 20;
      Serial.printf("R %lu %lu %.0f\n", t, rr, bpm);
    }
  }
  if (tickStim) {                             // intervalle écoulé sans battement
    tickStim = false;
    stimuler(t);
  }
  if (finStim != 0 && t >= finStim) { digitalWrite(PIN_STIM, LOW); finStim = 0; }
  if (finDet != 0 && t >= finDet) { digitalWrite(PIN_DET, LOW); finDet = 0; }
}

Ce que fait la question 20 : la fréquence cible fixe l'intervalle. À 60 bpm, la LED de stimulation s'allume si le cœur reste plus de 1 000 ms sans battre ; à 50 bpm, il faut 1 200 ms de silence.

\[T_{ech} = \frac{60\,000}{f}\] \[T_{ech} = \frac{60\,000}{60}\] \[T_{ech} = 1\,000\ \text{ms}\]

Tant que le cœur simulé bat plus vite que la fréquence cible, la LED de stimulation ne s'allume jamais.

Question 25 : un protocole de communication

Question 27 : mesurer la batterie avec l'ADC

Ce qu'il faut savoir.

  • L'ADC de l'ESP32 lit de 0 à 3,3 V ; une batterie lithium-ion monte à 4,2 V : il faut d'abord réduire la tension, avec un pont diviseur.
  • Pont de deux résistances \(R_1\) (côté batterie) et \(R_2\) (côté masse) : \(V_{ADC} = V_{bat}\,R_2 / (R_1 + R_2)\).
  • Des résistances de forte valeur (100 kΩ) limitent le courant que le pont prend à la batterie en permanence ; un condensateur de 100 nF sur l'entrée de l'ADC filtre le bruit.

Réponse. \(R_1 = R_2 = 100\) kΩ, entrée sur GPIO 35 (ADC1_CH7).

\[V_{ADC} = V_{bat}\,\frac{R_2}{R_1 + R_2}\] \[V_{ADC} = 4{,}2 \times \frac{100}{100 + 100}\] \[V_{ADC} = 2{,}1\ \text{V}\]

2,1 V est sous 3,3 V, avec une marge. À l'envers, dans le programme :

\[V_{bat} = 2 \times code \times \frac{3{,}3}{4095}\]

Exemple : le code lu vaut 2606.

\[V_{bat} = 2 \times 2606 \times \frac{3{,}3}{4095}\] \[V_{bat} \approx 4{,}20\ \text{V}\] 
const int PIN_BAT = 35;            // ADC1_CH7, milieu du pont 100 kΩ / 100 kΩ
float vBat = 0;

float lireBatterie() {
  long somme = 0;
  for (int i = 0; i < 16; i++) somme += analogRead(PIN_BAT);   // moyenne de 16 mesures
  return 2.0 * (somme / 16.0) * 3.3 / 4095.0;                     // le pont divise par 2
}

L'ADC de l'ESP32 n'est pas parfaitement linéaire : pour une mesure juste, on l'étalonne avec un multimètre (ou on utilise analogReadMilliVolts(), qui applique l'étalonnage d'usine).

Question 31 : rendre la maquette robuste

Réponse.

  • contrôle des paramètres : chaque réglage reçu est comparé à sa plage (fréquence de 30 à 180 bpm, seuil, période réfractaire) ; hors plage, il est refusé et l'ancien reste ; au démarrage, des valeurs sûres par défaut ;
  • garde-fou de fréquence : jamais deux stimulations à moins de 333 ms (180 bpm), quoi qu'il arrive dans le reste du programme ;
  • détection d'erreurs : signal plat, saturation, fréquence aberrante, batterie faible (questions 22 et 28), avec alerte ;
  • watchdog : remis à zéro une fois par tour de boucle ; s'il redémarre la puce, le programme le dit et repart avec les réglages par défaut (question 16) ;
  • interruptions courtes : elles lèvent un drapeau, la boucle fait le travail (TD 3, contraintes temporelles).
const unsigned long INTERVALLE_MIN = 333;   // ms : 180 bpm au plus

void stimuler(unsigned long t) {
  if (t - dernierEvt < INTERVALLE_MIN) return;   // trop tôt : on refuse, quoi qu'il arrive
  digitalWrite(PIN_STIM, HIGH);
  finStim = t + 20;
  dernierEvt = t;
}

À retenir

  • Interface web : / (page), /etat (JSON), /regler (réglage vérifié) ; ou MQTT avec des topics d'état et de configuration en JSON.
  • Batterie : pont diviseur par 2, \(V_{bat} = 2 \times code \times 3{,}3 / 4095\), seuils avec hystérésis.
  • Sous le seuil : prévenir, économiser, mais ne jamais arrêter la stimulation.
  • Robustesse : plages, valeurs par défaut, garde-fou de fréquence, détection d'erreurs, watchdog.

L'ECG de test

Pour tester sans générateur, l'ESP32 fabrique elle-même un ECG simplifié sur son DAC (8 bits, 0 à 255 pour 0 à 3,3 V), à la fréquence frequenceTest :

  • une ligne de base vers 1 V (code 77) ;
  • une onde R pointue de 20 ms qui monte à 2,55 V (code 197) ;
  • une onde T arrondie, 250 ms après, qui monte à 1,5 V (code 117).

Avec T0, le cœur simulé s'arrête : la maquette doit alors stimuler à la fréquence cible. Avec T45 et une fréquence cible de 60 bpm, le cœur bat trop lentement : la maquette stimule entre ses battements propres.

Le programme

// Pacemaker simulé, mode VVI : stimule si aucun battement n'est détecté pendant l'intervalle d'échappement.
#include <esp_task_wdt.h>

// ---------- broches ----------
const int PIN_DAC  = 25;   // ECG de test (DAC1), relié à GPIO 34
const int PIN_ECG  = 34;   // ECG simulé (ADC1_CH6)
const int PIN_STIM = 2;    // LED de stimulation
const int PIN_DET  = 4;    // LED battement détecté
const int PIN_BAT  = 35;   // batterie, pont diviseur par 2 (ADC1_CH7)

// ---------- paramètres réglables (interface série) ----------
int frequenceCible = 60;   // bpm : intervalle d'échappement 1000 ms
int seuil = 2500;          // code ADC de détection de l'onde R
int refractaire = 250;     // ms
int frequenceTest = 70;    // bpm de l'ECG de test ; 0 = cœur arrêté
const int HYSTERESIS = 200;
const unsigned long INTERVALLE_MIN = 333;   // garde-fou : 180 bpm au plus
const float SEUIL_BAT = 3.5;                // V

// ---------- timers (question 35) ----------
hw_timer_t *timerEch = NULL;    // 2 ms : 500 échantillons par seconde
hw_timer_t *timerStim = NULL;   // intervalle d'échappement
volatile bool tickEch = false;
volatile bool tickStim = false;
void IRAM_ATTR onEch()  { tickEch = true; }
void IRAM_ATTR onStim() { tickStim = true; }

// ---------- état ----------
unsigned long dernierEvt = 0;   // ms : dernier battement, détecté ou stimulé
unsigned long dernierR = 0;     // ms : dernier battement détecté
unsigned long rr = 0;           // ms
float bpm = 0;
bool auDessus = false;
unsigned long finStim = 0, finDet = 0, dernierBilan = 0;
int nbStim = 0, stimulationsDeSuite = 0;
int vMin = 4095, vMax = 0;
float vBat = 0;
unsigned long phase = 0;        // ms dans le battement de l'ECG de test

// ---------- ECG de test sur le DAC ----------
void genererECG() {
  int code = 77;                                   // ligne de base, environ 1 V
  if (frequenceTest > 0) {
    unsigned long periode = 60000UL / frequenceTest;
    phase += 2;
    if (phase >= periode) phase = 0;
    if (phase < 10) code = 77 + phase * 12;               // montée de l'onde R
    else if (phase < 20) code = 197 - (phase - 10) * 12;  // descente
    else if (phase >= 250 && phase < 350) {               // onde T
      int d = abs((int)phase - 300);
      code = 117 - d * 40 / 50;
    }
  }
  dacWrite(PIN_DAC, code);
}

// ---------- réglage de la fréquence cible ----------
void reglerFrequence(int f) {
  frequenceCible = f;
  timerAlarm(timerStim, 60000000UL / f, true, 0);   // en µs
  timerWrite(timerStim, 0);
}

// ---------- détection (questions 33 et 34) ----------
bool detecter(int v, unsigned long t) {
  if (t - dernierEvt < (unsigned long)refractaire) return false;
  if (!auDessus && v > seuil) { auDessus = true; return true; }
  if (auDessus && v < seuil - HYSTERESIS) auDessus = false;
  return false;
}

void battementDetecte(unsigned long t) {
  if (dernierR != 0) {
    rr = t - dernierR;
    bpm = 60000.0 / rr;                            // question 34
  }
  dernierR = t;
  dernierEvt = t;
  stimulationsDeSuite = 0;
  timerWrite(timerStim, 0);                        // stimulation inhibée
  tickStim = false;
  digitalWrite(PIN_DET, HIGH);
  finDet = t + 20;
  Serial.printf("R,%lu,%lu,%.1f\n", t, rr, bpm);   // question 37
}

// ---------- stimulation (question 36) ----------
void stimuler(unsigned long t) {
  if (t - dernierEvt < INTERVALLE_MIN) return;    // garde-fou
  digitalWrite(PIN_STIM, HIGH);
  finStim = t + 20;                                // LED allumée 20 ms
  dernierEvt = t;
  nbStim++;
  stimulationsDeSuite++;
  Serial.printf("S,%lu\n", t);
}

// ---------- surveillance du signal ----------
void surveillerECG(int v, unsigned long t) {
  vMin = min(vMin, v);
  vMax = max(vMax, v);
  if (t - dernierBilan < 2000) return;
  if (vMax - vMin < 100) Serial.println("ALERTE,signal plat");
  if (vMin <= 0 || vMax >= 4095) Serial.println("ALERTE,saturation");
  if (stimulationsDeSuite > 5) Serial.println("ALERTE,pas de rythme propre");
  vBat = 2.0 * analogRead(PIN_BAT) * 3.3 / 4095.0;
  if (vBat < SEUIL_BAT) Serial.printf("ALERTE,batterie,%.2f\n", vBat);
  Serial.printf("ETAT,%d,%.1f,%d,%.2f\n", frequenceCible, bpm, nbStim, vBat);
  vMin = 4095; vMax = 0;
  dernierBilan = t;
}

// ---------- commandes série (question 21) ----------
void lireSerie() {
  if (!Serial.available()) return;
  String cmd = Serial.readStringUntil('\n');
  cmd.trim();
  if (cmd.length() == 0) return;
  char c = cmd.charAt(0);
  long val = cmd.substring(1).toInt();
  if (c == 'F' && val >= 30 && val <= 180) reglerFrequence(val);
  else if (c == 'S' && val >= 100 && val <= 4000) seuil = val;
  else if (c == 'R' && val >= 100 && val <= 500) refractaire = val;
  else if (c == 'T' && val >= 0 && val <= 200) frequenceTest = val;
  else if (c != '?') { Serial.println("ERREUR,commande refusee"); return; }
  Serial.printf("PARAM,F=%d,S=%d,R=%d,T=%d\n", frequenceCible, seuil, refractaire, frequenceTest);
}

// ---------- démarrage ----------
void setup() {
  Serial.begin(115200);
  if (esp_reset_reason() == ESP_RST_TASK_WDT) Serial.println("ALERTE,redemarrage par le watchdog");
  pinMode(PIN_STIM, OUTPUT);
  pinMode(PIN_DET, OUTPUT);
  analogReadResolution(12);

  timerEch = timerBegin(1000000);                  // 1 pas = 1 µs
  timerAttachInterrupt(timerEch, &onEch);
  timerAlarm(timerEch, 2000, true, 0);             // toutes les 2 ms
  timerStim = timerBegin(1000000);
  timerAttachInterrupt(timerStim, &onStim);
  reglerFrequence(frequenceCible);

  esp_task_wdt_config_t config = { .timeout_ms = 2000, .idle_core_mask = 0, .trigger_panic = true };
  esp_task_wdt_reconfigure(&config);              // question 38
  esp_task_wdt_add(NULL);
  Serial.println("PRET,mode VVI");
}

// ---------- boucle ----------
void loop() {
  unsigned long t = millis();
  if (tickEch) {                                   // question 32 : un échantillon toutes les 2 ms
    tickEch = false;
    genererECG();
    int v = analogRead(PIN_ECG);
    surveillerECG(v, t);
    if (detecter(v, t)) battementDetecte(t);       // question 33
    esp_task_wdt_reset();                          // nourri seulement si un échantillon a été traité
  }
  if (tickStim) {                                  // intervalle écoulé sans battement
    tickStim = false;
    stimuler(t);
  }
  if (finStim != 0 && t >= finStim) { digitalWrite(PIN_STIM, LOW); finStim = 0; }
  if (finDet != 0 && t >= finDet) { digitalWrite(PIN_DET, LOW); finDet = 0; }
  lireSerie();
}

Avec T0, plus aucune onde R : une stimulation part 1 000 ms après le dernier battement, puis toutes les 1 000 ms (60 bpm). L'intervalle RR de 858 ms vient de l'ECG de test : \(60\,000 / 70 \approx 857\) ms, arrondi au pas de 2 ms. Les instants exacts dépendent du démarrage.

Deux limites à écrire dans le rapport :
