Télémétrie, batterie et sûreté

Un pacemaker se règle et se surveille de l'extérieur, vit des années sur une pile, et ne doit jamais faire défaut. Sur la maquette, cela devient une page web servie par l'ESP32, un protocole pour les réglages et les mesures, une surveillance de la batterie, et des garde-fous dans le logiciel.

Question 23 : une interface web sur l'ESP32

On te demande. Propose une interface web hébergée par l'ESP32 qui montre les paramètres du pacemaker.

Ce qu'il faut savoir.

  • Un serveur web embarqué : l'ESP32, connecté au Wi-Fi, répond aux requêtes HTTP GET d'un navigateur (modèle requête-réponse du chapitre 7).
  • On sépare la page (HTML, envoyée une fois) et les données (JSON, demandées toutes les secondes par la page) : la page se met à jour sans être rechargée.

Réponse. Trois adresses :

RequêteRéponse
GET /la page HTML du tableau de bord
GET /etatl'état en JSON : {"mode":"VVI","freq":60,"bpm":72,"rr":833,"stim":3,"bat":3.92}
GET /regler?freq=70applique un réglage (question 24), après vérification
#include <WiFi.h>
#include <WebServer.h>

WebServer serveur(80);

const char PAGE[] = R"(<!doctype html><meta charset="utf-8">
<h1>Pacemaker</h1><pre id="e">...</pre>
<script>
setInterval(async () => {
  const r = await fetch('/etat');
  document.getElementById('e').textContent = JSON.stringify(await r.json(), null, 1);
}, 1000);
</script>)";

void pageAccueil() { serveur.send(200, "text/html", PAGE); }

void pageEtat() {
  char json[128];
  snprintf(json, sizeof json,
    "{\"mode\":\"VVI\",\"freq\":%d,\"bpm\":%.0f,\"rr\":%lu,\"stim\":%d,\"bat\":%.2f}",
    frequenceCible, bpm, rr, nbStim, vBat);
  serveur.send(200, "application/json", json);
}

void pageRegler() {
  int f = serveur.arg("freq").toInt();
  if (f >= 30 && f <= 180) { reglerFrequence(f); serveur.send(200, "text/plain", "OK"); }
  else serveur.send(400, "text/plain", "valeur refusee");
}

void configWeb() {
  WiFi.begin("TON_WIFI", "TON_MOT_DE_PASSE");
  while (WiFi.status() != WL_CONNECTED) delay(200);   // une seule fois, au démarrage
  Serial.println(WiFi.localIP());                     // l'adresse à taper dans le navigateur
  serveur.on("/", pageAccueil);
  serveur.on("/etat", pageEtat);
  serveur.on("/regler", pageRegler);
  serveur.begin();
}
// dans loop() : serveur.handleClient();

Complément : le cours ne contient pas de document sur le serveur web embarqué ; ce code utilise la bibliothèque WebServer fournie avec le paquet ESP32 de l'Arduino IDE. Le sujet laisse aussi le choix de Node-RED ou de ThingSpeak, vus dans les labs.

Question 24 : modifier les paramètres à distance

Réponse. Par l'adresse /regler : un formulaire de la page, ou un lien comme http://192.168.1.42/regler?freq=70, envoie la nouvelle valeur ; l'ESP32 la vérifie (plage permise), l'applique et répond OK, ou refuse. Avec ThingSpeak ou MQTT (question 25), le réglage arrive par un message sur un topic auquel l'ESP32 est abonné. Dans tous les cas, les mêmes contrôles que pour la liaison série.

Question 25 : un protocole de communication

On te demande. Propose un protocole pour envoyer la configuration et recevoir les données de surveillance.

Réponse. MQTT, avec des messages JSON, comme dans le lab 6 : l'ESP32 publie son état et s'abonne à sa configuration ; le dashboard Node-RED fait l'inverse.

TopicQui publieMessage
pacemaker/etatESP32, toutes les secondes{"mode":"VVI","bpm":72,"rr":833,"stim":3,"bat":3.92}
pacemaker/evenementESP32, à chaque battement{"type":"R","t":125400} ou {"type":"S","t":126400}
pacemaker/alerteESP32, si besoin{"alerte":"batterie","v":3.41}
pacemaker/configdashboard{"freq":70,"seuil":2500,"refractaire":250}

Pourquoi MQTT :

  • publish-subscribe : plusieurs écrans peuvent suivre le même pacemaker sans que l'ESP32 le sache ;
  • messages courts, connexion permanente : la configuration arrive tout de suite, sans que l'ESP32 interroge ;
  • QoS 1 pour pacemaker/config et les alertes : le message est redélivré tant qu'il n'est pas acquitté.

Pour un vrai dispositif, la liaison devrait être chiffrée et authentifiée (MQTT sur TLS, identifiants) : un réglage envoyé par n'importe qui serait un danger.

Question 26 : le bloc Battery Check

Réponse. Il surveille la tension de la pile pour prévoir son remplacement. Un pacemaker vit plusieurs années sur une pile non rechargeable ; quand elle s'use, sa tension baisse. Le bloc mesure cette tension et prévient (par la télémétrie) assez tôt pour programmer le changement du boîtier, avant que la stimulation ne soit compromise. Sur la figure 2, c'est la fonction du bloc Power Supply.

Question 27 : mesurer la batterie avec l'ADC

Ce qu'il faut savoir.

  • L'ADC de l'ESP32 lit de 0 à 3,3 V ; une batterie lithium-ion monte à 4,2 V : il faut d'abord réduire la tension, avec un pont diviseur.
  • Pont de deux résistances \(R_1\) (côté batterie) et \(R_2\) (côté masse) : \(V_{ADC} = V_{bat}\,R_2 / (R_1 + R_2)\).
  • Des résistances de forte valeur (100 kΩ) limitent le courant que le pont prend à la batterie en permanence ; un condensateur de 100 nF sur l'entrée de l'ADC filtre le bruit.

Réponse. \(R_1 = R_2 = 100\) kΩ, entrée sur GPIO 35 (ADC1_CH7).

\[V_{ADC} = V_{bat}\,\frac{R_2}{R_1 + R_2}\] \[V_{ADC} = 4{,}2 \times \frac{100}{100 + 100}\] \[V_{ADC} = 2{,}1\ \text{V}\]

2,1 V est sous 3,3 V, avec une marge. À l'envers, dans le programme :

\[V_{bat} = 2 \times code \times \frac{3{,}3}{4095}\]

Exemple : le code lu vaut 2606.

\[V_{bat} = 2 \times 2606 \times \frac{3{,}3}{4095}\] \[V_{bat} \approx 4{,}20\ \text{V}\] 
const int PIN_BAT = 35;            // ADC1_CH7, milieu du pont 100 kΩ / 100 kΩ
float vBat = 0;

float lireBatterie() {
  long somme = 0;
  for (int i = 0; i < 16; i++) somme += analogRead(PIN_BAT);   // moyenne de 16 mesures
  return 2.0 * (somme / 16.0) * 3.3 / 4095.0;                     // le pont divise par 2
}

L'ADC de l'ESP32 n'est pas parfaitement linéaire : pour une mesure juste, on l'étalonne avec un multimètre (ou on utilise analogReadMilliVolts(), qui applique l'étalonnage d'usine).

Question 28 : surveiller le niveau

Réponse.

toutes les 10 s :
    vBat ← moyenne de 16 mesures
    vFiltree ← 0,9 × vFiltree + 0,1 × vBat         lisse les variations
    si vFiltree < SEUIL_ALERTE (3,5 V) pendant 3 bilans de suite :
        état ← « batterie faible », alerte (question 29)
    si vFiltree < SEUIL_CRITIQUE (3,3 V) :
        état ← « batterie critique »
    sinon si vFiltree > SEUIL_ALERTE + 0,1 V :
        état ← « normal »                           hystérésis : pas d'alerte qui clignote

Les seuils 3,5 V et 3,3 V conviennent à une batterie lithium-ion de maquette ; ce sont des choix à justifier, pas des valeurs du sujet.

Question 29 : sous le seuil d'alerte

Réponse. La maquette doit :

  • prévenir : message série, alerte sur le dashboard (pacemaker/alerte), LED qui clignote ;
  • garder la stimulation en priorité : c'est la fonction vitale, elle ne s'arrête jamais à cause de la batterie ;
  • économiser : publier moins souvent, couper le Wi-Fi entre deux envois, ne plus allumer les LED de confort ;
  • enregistrer l'instant de l'alerte, pour le rapport.

Un vrai stimulateur fait de même : quand sa pile atteint l'indicateur de remplacement (ERI, Elective Replacement Indicator), il le signale au programmateur, et le médecin planifie le changement du boîtier.

Question 31 : rendre la maquette robuste

Réponse.

  • contrôle des paramètres : chaque réglage reçu est comparé à sa plage (fréquence de 30 à 180 bpm, seuil, période réfractaire) ; hors plage, il est refusé et l'ancien reste ; au démarrage, des valeurs sûres par défaut ;
  • garde-fou de fréquence : jamais deux stimulations à moins de 333 ms (180 bpm), quoi qu'il arrive dans le reste du programme ;
  • détection d'erreurs : signal plat, saturation, fréquence aberrante, batterie faible (questions 22 et 28), avec alerte ;
  • watchdog : remis à zéro une fois par tour de boucle ; s'il redémarre la puce, le programme le dit et repart avec les réglages par défaut (question 16) ;
  • interruptions courtes : elles lèvent un drapeau, la boucle fait le travail (TD 3, contraintes temporelles).
const unsigned long INTERVALLE_MIN = 333;   // ms : 180 bpm au plus

void stimuler(unsigned long t) {
  if (t - dernierEvt < INTERVALLE_MIN) return;   // trop tôt : on refuse, quoi qu'il arrive
  digitalWrite(PIN_STIM, HIGH);
  finStim = t + 20;
  dernierEvt = t;
}

À retenir

  • Interface web : / (page), /etat (JSON), /regler (réglage vérifié) ; ou MQTT avec des topics d'état et de configuration en JSON.
  • Batterie : pont diviseur par 2, \(V_{bat} = 2 \times code \times 3{,}3 / 4095\), seuils avec hystérésis.
  • Sous le seuil : prévenir, économiser, mais ne jamais arrêter la stimulation.
  • Robustesse : plages, valeurs par défaut, garde-fou de fréquence, détection d'erreurs, watchdog.
