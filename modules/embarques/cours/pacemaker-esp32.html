Détecter et stimuler sur l'ESP32

La maquette reproduit les blocs du pacemaker avec une carte ESP32 : un ECG simulé entre par l'ADC, une LED tient lieu d'impulsion de stimulation, les timers donnent la base de temps. Il faut ensuite reconnaître un battement dans le signal, une seule fois par battement, et en déduire la fréquence cardiaque.

Question 9 : l'architecture de la maquette

On te demande. Propose une architecture matérielle qui reproduit les blocs du pacemaker avec une ESP32.

Réponse. Le cœur et la sonde sont remplacés par un ECG simulé, la stimulation par une LED, le programmateur par un PC (liaison série) et un navigateur (Wi-Fi).

  • L'ECG simulé peut venir d'un générateur de fonctions arbitraires, d'une deuxième carte qui joue un ECG enregistré (comme le simulateur du lab 7), ou de l'ESP32 elle-même : son DAC sur GPIO 25 sort un ECG de test, relié par un fil à l'entrée de l'ADC. C'est cette dernière solution que suit le programme de la question 32 : une seule carte suffit.
  • Un vrai signal d'électrode (quelques mV) demanderait un amplificateur d'instrumentation avant l'ADC ; le signal simulé est déjà dans la plage 0 à 3,3 V.

Question 11 : une impulsion périodique par timer

On te demande. Écris un programme Arduino qui génère périodiquement une impulsion de stimulation simulée avec un timer matériel.

Ce qu'il faut savoir.

  • Fréquence de stimulation et période : \(T = 60 / f\), avec \(f\) en battements par minute (bpm) et \(T\) en secondes. À 60 bpm, une impulsion par seconde.
  • Les fonctions du timer sont celles du TD 2 : timerBegin(1000000) (un pas par µs), timerAttachInterrupt, timerAlarm.
  • L'interruption ne fait que lever un drapeau ; la boucle allume la LED, puis l'éteint 20 ms plus tard sans delay(), en regardant millis().

Réponse.

const int PIN_STIM = 2;            // LED bleue de la carte
const int FREQ_BPM = 60;           // fréquence de stimulation
const int LARGEUR_MS = 20;         // durée d'allumage, visible à l'oeil

hw_timer_t *timerStim = NULL;
volatile bool impulsion = false;
unsigned long finImpulsion = 0;

void IRAM_ATTR onStim() {
  impulsion = true;                // l'interruption ne fait que lever le drapeau
}

void setup() {
  pinMode(PIN_STIM, OUTPUT);
  timerStim = timerBegin(1000000);                          // 1 pas = 1 µs
  timerAttachInterrupt(timerStim, &onStim);
  timerAlarm(timerStim, 60000000UL / FREQ_BPM, true, 0);   // 1 000 000 µs à 60 bpm
}

void loop() {
  if (impulsion) {
    impulsion = false;
    digitalWrite(PIN_STIM, HIGH);
    finImpulsion = millis() + LARGEUR_MS;
  }
  if (finImpulsion != 0 && millis() >= finImpulsion) {
    digitalWrite(PIN_STIM, LOW);
    finImpulsion = 0;
  }
}

La valeur de l'alarme : \(60 \times 10^6\ \mu\text{s} / f\). À 60 bpm, \(10^6\) pas ; à 75 bpm, 800 000 pas, soit 800 ms. Une vraie impulsion dure moins d'une milliseconde ; la LED reste allumée 20 ms pour qu'on la voie.

Question 12 : détecter un battement dans l'ECG

On te demande. Propose une méthode pour détecter un événement cardiaque dans un ECG simulé lu par l'ADC.

Ce qu'il faut savoir.

  • Sur un ECG, l'onde R (dépolarisation des ventricules) est la plus haute et la plus raide. Les ondes P et T sont plus basses et plus lentes.
  • Pour ne rater aucun pic, l'ECG est échantillonné régulièrement : 500 échantillons par seconde (une mesure toutes les 2 ms), cadencés par un timer.

Réponse. Méthode du seuil :

  • un timer lève un drapeau toutes les 2 ms ; la boucle lit alors l'ADC ;
  • on choisit un seuil au-dessus des ondes P et T et sous le sommet des ondes R (par exemple 60 % de la hauteur de l'onde R, mesurée au démarrage) ;
  • un événement est détecté au moment où le signal franchit le seuil en montant, c'est-à-dire quand l'échantillon précédent était en dessous et le courant au-dessus.

Améliorations possibles : filtrer avant (moyenne glissante sur quelques échantillons contre le bruit), ou travailler sur la pente (différence entre deux échantillons), qui fait ressortir l'onde R, très raide.

Questions 13 et 14 : l'algorithme à seuil, une seule détection par onde

On te demande. Écris un algorithme de détection à seuil, puis évite qu'une même onde soit détectée plusieurs fois.

Ce qu'il faut savoir.

  • Juste après un battement, le cœur est réfractaire : il ne peut pas en refaire un tout de suite. Le pacemaker fait pareil : pendant une période réfractaire (par exemple 250 ms), il ignore le signal.
  • Autour du seuil, le bruit fait monter et descendre le signal plusieurs fois : une hystérésis (redescendre nettement sous le seuil avant d'accepter un nouveau franchissement) évite les détections en rafale.

Réponse.

int seuil = 2500;                 // code ADC (12 bits)
const int HYSTERESIS = 200;       // il faut redescendre sous seuil - 200
int refractaire = 250;            // ms
bool auDessus = false;
unsigned long dernierEvt = 0;     // ms : instant du dernier battement

// appelée toutes les 2 ms avec le nouvel échantillon ; renvoie true si un battement commence
bool detecter(int v, unsigned long t) {
  if (t - dernierEvt < refractaire) {   // période réfractaire : on n'écoute pas
    return false;
  }
  if (!auDessus && v > seuil) {         // franchissement en montant
    auDessus = true;
    return true;
  }
  if (auDessus && v < seuil - HYSTERESIS) {
    auDessus = false;                   // le signal est bien redescendu
  }
  return false;
}

Sans période réfractaire, une onde R crochetée (deux sommets) ou bruitée compte deux battements, et la fréquence affichée double.

Question 15 : l'intervalle RR et la fréquence cardiaque

On te demande. Mesure le délai entre deux événements successifs et calcule la fréquence cardiaque à partir de l'intervalle RR.

Ce qu'il faut savoir. L'intervalle RR est le temps entre deux ondes R. Un battement toutes les RR secondes fait \(60 / RR\) battements par minute.

\[f_C = \frac{60\,000}{RR}\quad (f_C \text{ en bpm, } RR \text{ en ms})\]

Réponse. On note millis() à chaque détection ; la différence avec la détection précédente est l'intervalle RR.

unsigned long dernierR = 0;   // ms
unsigned long rr = 0;         // ms
float bpm = 0;

void battementDetecte(unsigned long t) {
  if (dernierR != 0) {
    rr = t - dernierR;
    bpm = 60000.0 / rr;
  }
  dernierR = t;
}

Exemple : deux ondes R à t = 12 400 ms et t = 13 200 ms.

\[RR = 13\,200 - 12\,400\] \[RR = 800\ \text{ms}\] \[f_C = \frac{60\,000}{800}\] \[f_C = 75\ \text{bpm}\]

Pour un affichage stable, on peut faire la moyenne des 4 à 8 derniers RR. La précision dépend de l'échantillonnage : à 2 ms près sur 800 ms, l'erreur est de 0,25 %.

Question 16 : le watchdog

On te demande. Propose une stratégie de gestion du watchdog pour détecter un blocage du programme.

Ce qu'il faut savoir. Le watchdog est un compteur que le programme doit remettre à zéro (le « nourrir ») avant la fin de son délai ; sinon, il redémarre la puce. Sur l'ESP32, le Task Watchdog (TWDT) surveille les tâches qui s'y sont inscrites.

Réponse.

  • délai de 2 s : bien plus long qu'un tour de boucle normal (quelques millisecondes), assez court pour ne pas laisser le patient longtemps sans surveillance ;
  • la remise à zéro se fait une fois par tour de loop(), là où se font la détection et la stimulation ; jamais dans une interruption de timer, qui continuerait d'arriver pendant que la boucle est bloquée ;
  • on ne nourrit le chien que si la boucle a vraiment avancé : par exemple si un échantillon a été traité depuis le dernier tour (sinon le timer d'échantillonnage est arrêté) ;
  • au redémarrage, le programme regarde la cause (esp_reset_reason()) : si c'est le watchdog, il le signale par la liaison série et repart avec des paramètres sûrs par défaut.
#include <esp_task_wdt.h>

void configWatchdog() {
  esp_task_wdt_config_t config = {
    .timeout_ms = 2000,       // 2 s sans remise à zéro : redémarrage
    .idle_core_mask = 0,      // ne pas surveiller les tâches de repos
    .trigger_panic = true     // redémarrer la puce
  };
  esp_task_wdt_reconfigure(&config);   // le paquet l'a déjà démarré : on change son réglage
  esp_task_wdt_add(NULL);              // surveiller la tâche qui exécute loop()
}

// dans loop(), une fois par tour :
//   esp_task_wdt_reset();

Si ta version du paquet ESP32 n'a pas démarré le watchdog, esp_task_wdt_init(&config) remplace esp_task_wdt_reconfigure. Le cours (chapitre 5) décrit les trois chiens de garde matériels de l'ESP32, pas ces fonctions.

À retenir

  • Maquette : ECG simulé (DAC) vers ADC1, LED pour la stimulation, timers, UART et Wi-Fi.
  • Détection : franchissement du seuil en montant, puis période réfractaire et hystérésis.
  • \(f_C = 60\,000 / RR\) avec RR en ms ; alarme du timer de stimulation : \(60 \times 10^6 / f\) µs.
  • Watchdog nourri une fois par tour de boucle, jamais dans une interruption.
