Partie 1 : la semelle instrumentée et connectée

Ce que dit le cours

  • Le besoin : chez le diabétique, les nerfs du pied sont abîmés. Le patient ne sent ni la surcharge ni la plaie qui commence. L'ulcère évolue en six stades, du stade 0 (pas de lésion) à la gangrène de tout le pied (stade 5). Le but est d'agir au stade 0.
  • Ce que la semelle mesure : la force d'appui en 16 points, la température et l'humidité, la bio-impédance des tissus (circuit MAX30009).
  • Les capteurs de force : 16 capteurs résistifs. Leur résistance baisse quand on appuie (plus de 1 MΩ au repos). Plage de 500 g à 10 kg, temps de réponse inférieur à 10 µs, IP67.
  • Le schéma bloc : trois blocs de mesure (BioZ, gestion des capteurs d'appui plantaire, température et humidité) reliés au µC, qui envoie par le bloc TX Radio et son antenne. La gestion de l'alimentation tire l'énergie d'un accumulateur.
  • Pourquoi c'est un système embarqué : une seule tâche, autonome sur accumulateur, très peu de place.

1. Pourquoi une semelle et pas une simple consultation régulière chez le médecin ?

Voir la réponse

Le patient ne sent plus la surcharge ni la plaie : il ne peut pas donner l'alerte lui-même.

La plaie peut passer d'un stade à l'autre entre deux consultations.

La semelle mesure en continu ce que le patient ne sent plus, pour agir au stade 0.

2. Un patient de 90 kg pose tout son poids sur le talon, porté par 3 capteurs. Le capteur suffit-il ?

Voir la réponse

Charge par capteur = poids porté / nombre de capteurs chargés.

Charge = 90 / 3

Charge = 30 kg par capteur.

La plage s'arrête à 10 kg : le capteur sature et lit 10 kg au plus. La fiche se vérifie pour le pire cas, pas pour le cas moyen.

Voir la réponse

Le tableau des entrées-sorties

Pour l'entraînement, on simplifie : 4 capteurs d'appui seulement (talon, premier et cinquième métatarsiens, gros orteil), un capteur de température et d'humidité en I2C, une LED d'alerte. La vraie semelle en a 16 : ils passent par le bloc « gestion des capteurs d'appui plantaire », que le cours ne détaille pas.

Les règles à appliquer viennent du chapitre 5 :

  • la semelle envoie en Wi-Fi, donc les mesures analogiques vont sur l'ADC1 (l'ADC2 est inutilisable avec le Wi-Fi) ;
  • GPIO 34, 35, 36 et 39 sont des entrées seulement : parfaites pour des capteurs, impossibles pour une LED ;
  • I2C par défaut : SDA sur GPIO 21, SCL sur GPIO 22.

5. Un capteur donne 1,65 V. Quel code lit le programme (ADC 12 bits) ? Et quelle tension pour un code de 3276 ?

Voir la réponse

\(ADC\_OUT = 4095 \times \dfrac{ADC\_IN}{3{,}3\ \text{V}}\)

\(ADC\_OUT = 4095 \times \dfrac{1{,}65}{3{,}3}\)

\(ADC\_OUT \approx 2048\) (2047,5, arrondi par le convertisseur).

À l'inverse : \(ADC\_IN = ADC\_OUT \times \dfrac{3{,}3}{4095}\)

\(ADC\_IN = 3276 \times \dfrac{3{,}3}{4095}\)

\(ADC\_IN \approx 2{,}64\) V.

L'organigramme

L'organigramme suit l'ordre du programme : setup() une seule fois, puis loop() qui tourne sans fin. Le callback n'est pas dans la boucle : c'est client.loop() qui l'appelle quand un message arrive.

6. Dessine l'organigramme du programme de la semelle avant de regarder.

Voir la réponse

Après la publication (ou si la seconde n'est pas écoulée), on revient au début de loop().

Le « toutes les 1 s » se fait avec millis(), pas avec delay(1000) : pendant un delay, client.loop() ne tourne pas et les commandes attendent.

Partie 2 : les fonctions d'un objet connecté en MQTT

Le squelette du cours, en sept étapes

  1. Déclaration des bibliothèques : WiFi.h, PubSubClient.h.
  2. Déclaration des paramètres : réseau Wi-Fi, serveur MQTT.
  3. Création des objets : espClient, client.
  4. setup() : port série, Wi-Fi, client.setServer(mqtt_server, 1883), client.setCallback(callback), broches.
  5. callback() : lecture du message et décision.
  6. reconnect() : se reconnecter au broker et se réabonner.
  7. loop() : reconnexion, acquisition, publication des messages.

Chaque fonction a un seul rôle :

FonctionQuand elle tourneCe qu'elle fait
setup()Une fois, au démarragePrépare tout : Wi-Fi, broker, callback, broches.
callback()À chaque message reçu sur un topic abonnéReconstruit le message caractère par caractère, regarde le topic, agit.
reconnect()Quand la connexion au broker est perdueSe reconnecte avec un Client ID, se réabonne aux topics.
loop()Sans finVérifie la connexion, fait tourner client.loop(), mesure et publie à intervalle régulier.
Fonction de traitementAppelée par loop() ou callback()Transforme une mesure brute en valeur utile ou en décision.

Le callback

Sa signature est imposée par la bibliothèque PubSubClient : le topic, le message en octets, sa longueur. Le message n'est pas une chaîne : on le reconstruit dans une String.

void callback(char* topic, byte* message, unsigned int length) {
  String messageTemp;
  for (int i = 0; i < length; i++) {
    messageTemp += (char)message[i];
  }
  if (String(topic) == "ensam/gbm/light") {
    if (messageTemp == "on") {
      digitalWrite(ledPin, HIGH);
    }
    else if (messageTemp == "off") {
      digitalWrite(ledPin, LOW);
    }
  }
}

La fonction de traitement

Une fonction de traitement prend une mesure et rend une valeur utile : une tension, une moyenne, un maximum, une alerte. On la sort de loop() pour que loop() reste lisible et pour la réutiliser.

8. Écris float tension(int code) qui convertit un code ADC 12 bits en volts.

Voir la correction 
float tension(int code) {
  return 3.3 * code / 4095.0;
}

C'est la formule du cours à l'envers : \(ADC\_IN = ADC\_OUT \times 3{,}3 / 4095\).

Écrire 4095.0 et non 4095 : avec deux entiers, la division serait entière et tronquée.

9. Écris int zoneMax(float v[], int n) qui rend l'indice de la zone la plus chargée.

Voir la correction 
int zoneMax(float v[], int n) {
  int k = 0;
  for (int i = 1; i < n; i++) {
    if (v[i] > v[k]) {
      k = i;
    }
  }
  return k;
}

On part de la zone 0, on garde l'indice de la plus grande valeur vue.

On rend l'indice et pas la valeur : il dit où est la surcharge.

10. Écris float moyenne(float v[], int n), puis dis comment l'utiliser pour lisser une mesure qui bruite.

Voir la correction 
float moyenne(float v[], int n) {
  float somme = 0;
  for (int i = 0; i < n; i++) {
    somme += v[i];
  }
  return somme / n;
}

Pour lisser : lire le même capteur plusieurs fois de suite (par exemple 10 fois), ranger les valeurs dans un tableau, publier la moyenne.

La loop

Le cours lui donne trois rôles, dans cet ordre : reconnexion, acquisition, publication. L'intervalle se mesure avec millis() pour ne jamais bloquer client.loop().

void loop() {
  if (!client.connected()) {
    reconnect();
  }
  client.loop();
  long now = millis();
  if (now - lastMsg > 2000) {
    lastMsg = now;
    temp = 1.5 * analogRead(A0) / 600;
    char tempString[8];
    dtostrf(temp, 1, 2, tempString);
    client.publish("ensam/gbm/temperature", tempString);
  }
}

publish envoie du texte : dtostrf(valeur, largeur, décimales, tableau) écrit le nombre dans un tableau de caractères.

Les trois rôles sont là, dans l'ordre : reconnexion, acquisition (et traitement), publication.

Le seuil de 2,5 V est un choix pour l'exercice : le cours ne donne pas de seuil.

12. Trouve les quatre erreurs de ce programme. L'ESP32 se connecte, mais la LED ne réagit jamais aux commandes et, après une coupure du broker, plus rien n'arrive.

void setup() {
  Serial.begin(115200);
  setup_wifi();
  client.setServer(mqtt_server, 1883);
  pinMode(ledPin, OUTPUT);
  client.connect("ESP32-semelle");
  client.subscribe("semelle/cmd");
}

void loop() {
  if (!client.connected()) {
    client.connect("ESP32-semelle");
  }
  float v = tension(analogRead(36));
  char vString[8];
  dtostrf(v, 1, 2, vString);
  client.publish("semelle/talon", vString);
  delay(5000);
}
Voir la correction

Pas de client.setCallback(callback) dans setup() : la bibliothèque ne sait pas quelle fonction appeler.

Pas de client.loop() dans loop() : les messages reçus ne sont jamais traités, le callback n'est jamais appelé.

La reconnexion ne se réabonne pas : après une coupure, l'ESP32 est reconnecté mais n'écoute plus semelle/cmd. C'est le rôle de reconnect() : se connecter puis s'abonner.

delay(5000) bloque tout pendant 5 s : remplacer par le test now - lastMsg > 5000 avec millis().

Le programme complet de la semelle

13. Assemble tout : quatre capteurs, traitement, alerte, commandes, et un seul message JSON par seconde sur semelle/appui. Essaie seul, puis compare.

Voir la correction 
#include <WiFi.h>
#include <PubSubClient.h>
#include <ArduinoJson.h>

const char* ssid = "TON_WIFI";
const char* password = "TON_MOT_DE_PASSE";
const char* mqtt_server = "test.mosquitto.org";

WiFiClient espClient;
PubSubClient client(espClient);

const int capteurs[4] = {36, 39, 34, 35};          // ADC1, entrées seules
const char* zones[4] = {"talon", "m1", "m5", "orteil"};
const int ledPin = 2;                              // LED d'alerte
const float SEUIL = 2.5;                           // V, choisi pour l'exercice

long lastMsg = 0;
bool mesure = true;

void setup_wifi() {
  delay(10);
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("WiFi connected");
}

// Fonctions de traitement
float tension(int code) {
  return 3.3 * code / 4095.0;
}

int zoneMax(float v[], int n) {
  int k = 0;
  for (int i = 1; i < n; i++) {
    if (v[i] > v[k]) {
      k = i;
    }
  }
  return k;
}

// Callback : lecture du message et décision
void callback(char* topic, byte* message, unsigned int length) {
  String messageTemp;
  for (int i = 0; i < length; i++) {
    messageTemp += (char)message[i];
  }
  if (String(topic) == "semelle/cmd") {
    if (messageTemp == "start") {
      mesure = true;
    }
    else if (messageTemp == "stop") {
      mesure = false;
    }
  }
}

void reconnect() {
  while (!client.connected()) {
    if (client.connect("ESP32-semelle")) {
      client.subscribe("semelle/cmd");
    } else {
      delay(5000);
    }
  }
}

void setup() {
  Serial.begin(115200);
  setup_wifi();
  client.setServer(mqtt_server, 1883);
  client.setCallback(callback);
  pinMode(ledPin, OUTPUT);
}

// Loop : reconnexion, acquisition, traitement, publication
void loop() {
  if (!client.connected()) {
    reconnect();
  }
  client.loop();
  long now = millis();
  if (mesure && now - lastMsg > 1000) {
    lastMsg = now;
    float v[4];
    StaticJsonDocument<200> doc;
    for (int i = 0; i < 4; i++) {
      v[i] = tension(analogRead(capteurs[i]));
      doc[zones[i]] = v[i];
    }
    int k = zoneMax(v, 4);
    bool alerte = v[k] > SEUIL;
    digitalWrite(ledPin, alerte ? HIGH : LOW);
    doc["max"] = zones[k];
    doc["alerte"] = alerte;
    char msg[200];
    serializeJson(doc, msg);
    client.publish("semelle/appui", msg);
  }
}

Le message publié ressemble à {"talon":2.71,"m1":0.84,"m5":0.40,"orteil":1.12,"max":"talon","alerte":true}.

Le lab 2 écrit le JSON sur le port série (serializeJson(doc, Serial)). Ici on l'écrit dans un tableau de caractères (serializeJson(doc, msg)) pour pouvoir le publier.

Le capteur de température et d'humidité en I2C n'est pas dans le programme : le cours ne dit pas quel circuit la semelle utilise, donc pas quelle bibliothèque.

Les pièges

  • Oublier client.setCallback(callback) ou client.loop() : aucun message reçu n'est traité.
  • S'abonner dans setup() seulement : l'abonnement est perdu à la première reconnexion. On s'abonne dans reconnect().
  • Comparer le topic avec topic == "…" : topic est un char*, il faut String(topic) == "…".
  • Publier un float directement : publish veut du texte, d'où dtostrf ou le JSON.
  • Mettre delay() dans loop() : tout est bloqué, on mesure l'intervalle avec millis().
  • Un capteur analogique sur l'ADC2 avec le Wi-Fi, ou une LED sur GPIO 34 à 39 (entrées seules).
  • Deux cartes avec le même Client ID sur un broker public : elles se déconnectent l'une l'autre.
