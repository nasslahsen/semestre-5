Partie 1 : la semelle instrumentée et connectée

Ce que dit le cours

  • Le besoin : chez le diabétique, les nerfs du pied sont abîmés. Le patient ne sent ni la surcharge ni la plaie qui commence. L'ulcère évolue en six stades, du stade 0 (pas de lésion) à la gangrène de tout le pied (stade 5). Le but est d'agir au stade 0.
  • Ce que la semelle mesure : la force d'appui en 16 points, la température et l'humidité, la bio-impédance des tissus (circuit MAX30009).
  • Les capteurs de force : 16 capteurs résistifs. Leur résistance baisse quand on appuie (plus de 1 MΩ au repos). Plage de 500 g à 10 kg, temps de réponse inférieur à 10 µs, IP67.
  • Le schéma bloc : trois blocs de mesure (BioZ, gestion des capteurs d'appui plantaire, température et humidité) reliés au µC, qui envoie par le bloc TX Radio et son antenne. La gestion de l'alimentation tire l'énergie d'un accumulateur.
  • Pourquoi c'est un système embarqué : une seule tâche, autonome sur accumulateur, très peu de place.

1. Pourquoi une semelle et pas une simple consultation régulière chez le médecin ?

Voir la réponse

Le patient ne sent plus la surcharge ni la plaie : il ne peut pas donner l'alerte lui-même.

La plaie peut passer d'un stade à l'autre entre deux consultations.

La semelle mesure en continu ce que le patient ne sent plus, pour agir au stade 0.

2. Un patient de 90 kg pose tout son poids sur le talon, porté par 3 capteurs. Le capteur suffit-il ?

Voir la réponse

Charge par capteur = poids porté / nombre de capteurs chargés.

Charge = 90 / 3

Charge = 30 kg par capteur.

La plage s'arrête à 10 kg : le capteur sature et lit 10 kg au plus. La fiche se vérifie pour le pire cas, pas pour le cas moyen.

5. Un capteur donne 1,65 V. Quel code lit le programme (ADC 12 bits) ? Et quelle tension pour un code de 3276 ?

Voir la réponse

\(ADC\_OUT = 4095 \times \dfrac{ADC\_IN}{3{,}3\ \text{V}}\)

\(ADC\_OUT = 4095 \times \dfrac{1{,}65}{3{,}3}\)

\(ADC\_OUT \approx 2048\) (2047,5, arrondi par le convertisseur).

À l'inverse : \(ADC\_IN = ADC\_OUT \times \dfrac{3{,}3}{4095}\)

\(ADC\_IN = 3276 \times \dfrac{3{,}3}{4095}\)

\(ADC\_IN \approx 2{,}64\) V.

L'organigramme

L'organigramme suit l'ordre du programme : setup() une seule fois, puis loop() qui tourne sans fin. Le callback n'est pas dans la boucle : c'est client.loop() qui l'appelle quand un message arrive.

6. Dessine l'organigramme du programme de la semelle avant de regarder.

Voir la réponse

Après la publication (ou si la seconde n'est pas écoulée), on revient au début de loop().

Le « toutes les 1 s » se fait avec millis(), pas avec delay(1000) : pendant un delay, client.loop() ne tourne pas et les commandes attendent.

Partie 2 : les fonctions d'un objet connecté en MQTT

Le squelette du cours, en sept étapes

  1. Déclaration des bibliothèques : WiFi.h, PubSubClient.h.
  2. Déclaration des paramètres : réseau Wi-Fi, serveur MQTT.
  3. Création des objets : espClient, client.
  4. setup() : port série, Wi-Fi, client.setServer(mqtt_server, 1883), client.setCallback(callback), broches.
  5. callback() : lecture du message et décision.
  6. reconnect() : se reconnecter au broker et se réabonner.
  7. loop() : reconnexion, acquisition, publication des messages.

Chaque fonction a un seul rôle :

FonctionQuand elle tourneCe qu'elle fait
setup()Une fois, au démarragePrépare tout : Wi-Fi, broker, callback, broches.
callback()À chaque message reçu sur un topic abonnéReconstruit le message caractère par caractère, regarde le topic, agit.
reconnect()Quand la connexion au broker est perdueSe reconnecte avec un Client ID, se réabonne aux topics.
loop()Sans finVérifie la connexion, fait tourner client.loop(), mesure et publie à intervalle régulier.
Fonction de traitementAppelée par loop() ou callback()Transforme une mesure brute en valeur utile ou en décision.

Le callback

Sa signature est imposée par la bibliothèque PubSubClient : le topic, le message en octets, sa longueur. Le message n'est pas une chaîne : on le reconstruit dans une String.

void callback(char* topic, byte* message, unsigned int length) {
  String messageTemp;
  for (int i = 0; i < length; i++) {
    messageTemp += (char)message[i];
  }
  if (String(topic) == "ensam/gbm/light") {
    if (messageTemp == "on") {
      digitalWrite(ledPin, HIGH);
    }
    else if (messageTemp == "off") {
      digitalWrite(ledPin, LOW);
    }
  }
}

La fonction de traitement

Une fonction de traitement prend une mesure et rend une valeur utile : une tension, une moyenne, un maximum, une alerte. On la sort de loop() pour que loop() reste lisible et pour la réutiliser.

La loop

Le cours lui donne trois rôles, dans cet ordre : reconnexion, acquisition, publication. L'intervalle se mesure avec millis() pour ne jamais bloquer client.loop().

void loop() {
  if (!client.connected()) {
    reconnect();
  }
  client.loop();
  long now = millis();
  if (now - lastMsg > 2000) {
    lastMsg = now;
    temp = 1.5 * analogRead(A0) / 600;
    char tempString[8];
    dtostrf(temp, 1, 2, tempString);
    client.publish("ensam/gbm/temperature", tempString);
  }
}

publish envoie du texte : dtostrf(valeur, largeur, décimales, tableau) écrit le nombre dans un tableau de caractères.

Partie 3 : la semelle programmée (TD 2)

Le montage du professeur

Chaque réseau de 8 capteurs passe par le multiplexeur NX3L4051, puis par l'AOP qui donne \(V_A\), lue par l'ADC. Le programme fait le chemin à l'envers : du code lu à la tension, puis à la résistance, puis à la force.

À retenirValeur
Tension de l'entrée + de l'AOP\(V^+ = 3{,}3 \times 10 / 120 = 0{,}275\) V
Tension AIN1\(V_A = V^+ \left(1 + R_G / R_{FSR}\right)\), avec \(R_G = 750\) kΩ
Code vers tension\(V_A = \text{code} \times 3{,}3 / 4095\)
Tension vers résistance\(R_{FSR} = R_G / (V_A / V^+ - 1)\)
Résistance vers force\(F = \beta / (R_{FSR} - R_0)\), \(\beta = 629\) kΩ·N, \(R_0 = 71\) kΩ

15. Écris selectSensor(int num). Que valent S3 S2 S1 pour num = 6 ?

Voir la correction 
void selectSensor(int num) {
  digitalWrite(S1, (num >> 0) & 1);   // bit 0, poids faible
  digitalWrite(S2, (num >> 1) & 1);   // bit 1
  digitalWrite(S3, (num >> 2) & 1);   // bit 2, poids fort
}

6 s'écrit 110 : S3 = 1, S2 = 1, S1 = 0. Le multiplexeur relie \(Y_6\) à Z.

Le décalage >> i amène le bit voulu tout à droite ; le masque & 1 efface les autres.

16. Le capteur sélectionné donne le code 2457. Calcule \(V_A\), puis \(R_{FSR}\), puis la force.

Voir la correction

Tension :

\[V_A = \text{code} \times \frac{3{,}3}{4095}\] \[V_A = 2457 \times \frac{3{,}3}{4095}\] \[V_A = 1{,}98\ \text{V}\]

Résistance :

\[R_{FSR} = \frac{R_G}{V_A / V^+ - 1}\] \[R_{FSR} = \frac{750}{1{,}98 / 0{,}275 - 1}\] \[R_{FSR} \approx 121\ \text{k}\Omega\]

Force :

\[F = \frac{\beta}{R_{FSR} - R_0}\] \[F = \frac{629}{121 - 71}\] \[F \approx 12{,}6\ \text{N}\]

17. Écris float rsensor(float val). Pourquoi faut-il un test avant la division ?

Voir la correction 
float rsensor(float val) {
  float va = val * 3.3 / 4095.0;      // code -> tension
  if (va <= VP) return INFINITY;      // pas d'appui
  return RG / (va / VP - 1.0);        // ohms
}

Sans appui, \(V_A\) vaut \(V^+\) ; avec le bruit, elle peut passer un peu dessous.

Le dénominateur deviendrait nul ou négatif : division par zéro, ou résistance négative.

18. Écris acquisition(int mode, int num, int N) (mode 0 : une mesure de num ; mode 1 : moyenne de N mesures de num ; mode 2 : moyenne de N mesures pour chacun des 8). Que moyennes-tu, et pourquoi ?

Voir la correction 
float mesures[8];

float moyenneCodes(int num, int N) {
  if (N < 1) N = 1;
  selectSensor(num);
  delay(2);                                 // VA se stabilise
  long somme = 0;
  for (int i = 0; i < N; i++) somme += analogRead(AIN1);

void acquisition(int mode, int num, int N) {
  if (mode == 0) mesures[num] = rsensor(sensorAcquisition(num));
  else if (mode == 1) mesures[num] = rsensor(moyenneCodes(num, N));

20. Trouve les quatre erreurs de ce programme.

hw_timer_t *timer = NULL;

void IRAM_ATTR onTimer0() {
  tick = true;
  acquisition(2, 0, 10);
}

void setup() {
  timer = timerBegin(1000000);
  timerAttachInterrupt(timer, &onTimer);
  timerAlarm(timer, 1000000, true, 0);
}

void loop() {
  if (tick) {
    tick = false;
    delay(1000);
  }
}
Voir la correction
  • tick n'est pas déclaré : il faut volatile bool tick = false;.
  • La fonction s'appelle onTimer0, mais on attache &onTimer : les deux noms doivent être les mêmes (c'est l'erreur de l'annexe du TD 2).
  • L'acquisition est dans l'interruption : bien trop long, elle va dans loop().
  • Le delay(1000) dans loop() bloque tout et ne sert à rien : c'est le timer qui donne le rythme.

Partie 4 : architecture et composants (TD 3)

Ce que dit le cours

  • Système embarqué : système électronique et informatique autonome, dédié à une tâche bien précise ; il désigne le matériel et le logiciel. Ressources limitées : énergie, place.
  • RISC : instructions simples d'un cycle, registre à registre, complexité dans le logiciel. CISC : instructions complexes de plusieurs cycles, mémoire à mémoire, complexité dans le matériel.
  • Von Neumann : une mémoire et un bus pour tout. Harvard : mémoire du programme et mémoire des données séparées. Super Harvard : Harvard plus un cache d'instructions et un contrôleur d'entrées-sorties.
  • DMA : transferts entre périphériques et mémoire sans le CPU.

23. Rôle de : PWM, watchdog, timer, UART, pile. Une PWM vaut \(+E\) pendant \(\alpha T\) et \(-E\) le reste de la période : que vaut sa moyenne pour \(\alpha = 0{,}8\) ?

Voir la correction

D'après la correction faite en classe :

  • PWM : générateur de signaux avec des impulsions de largeur variable.
  • Watchdog : chien de garde, circuit de réinitialisation automatique du microcontrôleur en cas de blocage.
  • Timer : génère des temporisations programmables.
  • UART : circuit de transmission asynchrone.
  • Pile (stack) : zone mémoire LIFO (Last In, First Out) pour stocker temporairement les données et les arguments des fonctions.

Moyenne de la PWM :

\[\langle u \rangle = \alpha E - (1 - \alpha) E = (2\alpha - 1) E\] \[\langle u \rangle = (2 \times 0{,}8 - 1) E\] \[\langle u \rangle = 0{,}6\,E\]

24. Une boucle de 20 instructions, chacune avec une donnée. Combien de cycles de bus en Von Neumann, en Harvard (modèle du cours) ? Pourquoi cette différence ?

Voir la correction

Von Neumann : \(2N = 40\) cycles. Harvard : \(N + 1 = 21\) cycles.

En Harvard, la donnée de l'instruction \(k\) passe sur le bus des données pendant que l'instruction \(k + 1\) arrive sur le bus du programme. En Von Neumann, tout fait la queue sur le même bus.

25. Compare la gestion des entrées-sorties par scrutation ou interruption et par DMA. Laquelle pour un bouton ? Pour un ECG à 2 000 échantillons par seconde ?

Voir la correction

Scrutation ou interruption : chaque donnée passe par le CPU, simple, mais le CPU attend (scrutation) ou est dérangé à chaque donnée (interruption).

DMA : la donnée va directement en mémoire, le CPU reste libre ; configuration plus lourde.

Bouton : une interruption. ECG rapide : le DMA.

26. Dans le schéma du PIC, quel bloc garde le programme ? Les variables ? Un réglage à garder sans alimentation ? L'adresse de la prochaine instruction ? Les adresses de retour ?

Voir la correction
  • Le programme : Program Memory (flash).
  • Les variables : Data Memory (RAM).
  • Un réglage à garder : Data EEPROM.
  • La prochaine instruction : Program Counter.
  • Les adresses de retour : la pile (16 niveaux).

Deux mémoires séparées : Harvard. 83 instructions : RISC.

27. Une boucle principale dure 40 ms sans interruption. Une interruption arrive toutes les 8 ms, bloquée pendant sa routine. a) Durée maximale de la routine ? b) La routine dure 2 ms : durée moyenne de la boucle ? c) Que se passe-t-il si la routine dure 9 ms ? d) Et si, en plus, elle réarme les interruptions ?

Voir la correction

a) La routine doit finir avant l'interruption suivante : \(t_{max} = T = 8\) ms.

b) La boucle n'avance que pendant \(1 - 2/8 = 75\ \%\) du temps :

\[t_{boucle} = \frac{t_0}{1 - t / T}\] \[t_{boucle} = \frac{40}{1 - 2 / 8}\] \[t_{boucle} \approx 53{,}3\ \text{ms}\]

c) Les demandes arrivent pendant la routine : elles attendent, le retard s'accumule, des interruptions sont perdues, et la boucle ne s'exécute plus.

d) Les routines s'imbriquent, chacune laisse son contexte sur la pile, qui déborde : le programme plante.

Partie 5 : le pacemaker (projet)

Le projet est surtout un travail pratique, mais il utilise exactement les notions de l'examen : ADC, timer, interruption, watchdog.

28. Que veut dire VVI ? Pourquoi est-ce le mode de la maquette ?

Voir la correction

V : ventricule stimulé. V : ventricule détecté. I : stimulation inhibée quand un battement est détecté.

La maquette stimule si rien n'est détecté pendant l'intervalle et s'inhibe sinon, sur une seule voie.

29. Deux ondes R sont détectées à 3 790 ms et 4 650 ms. Fréquence cardiaque ?

Voir la correction \[RR = 4\,650 - 3\,790 = 860\ \text{ms}\] \[f_C = \frac{60\,000}{RR}\] \[f_C = \frac{60\,000}{860}\] \[f_C \approx 69{,}8\ \text{bpm}\]

30. Fréquence cible 48 bpm. Au bout de combien de temps sans battement la maquette stimule-t-elle ? Que fait-elle si un battement arrive avant ?

Voir la correction \[T_{ech} = \frac{60\,000}{f}\] \[T_{ech} = \frac{60\,000}{48}\] \[T_{ech} = 1\,250\ \text{ms}\]

Si un battement arrive avant, elle ne stimule pas et remet le timer de stimulation à zéro (timerWrite(timer, 0)) : l'intervalle repart de ce battement.

31. Pourquoi une période réfractaire après chaque détection ? Où remettre le watchdog à zéro ?

Voir la correction

Sans elle, une onde R bruitée ou à deux sommets franchit le seuil deux fois : un battement compté double, une fréquence fausse.

Le watchdog se remet à zéro une fois par tour de loop(), jamais dans une interruption : une interruption de timer continue d'arriver quand la boucle est bloquée, et le watchdog ne verrait rien.

Les pièges

  • Oublier client.setCallback(callback) ou client.loop() : aucun message reçu n'est traité.
  • S'abonner dans setup() seulement : l'abonnement est perdu à la première reconnexion. On s'abonne dans reconnect().
  • Comparer le topic avec topic == "…" : topic est un char*, il faut String(topic) == "…".
  • Publier un float directement : publish veut du texte, d'où dtostrf ou le JSON.
  • Mettre delay() dans loop() : tout est bloqué, on mesure l'intervalle avec millis().
  • Un capteur analogique sur l'ADC2 avec le Wi-Fi, ou une LED sur GPIO 34 à 39 (entrées seules).
  • Deux cartes avec le même Client ID sur un broker public : elles se déconnectent l'une l'autre.
  • Lire S3 S2 S1 à l'envers : S1 est le bit de poids faible (111 = 7, 011 = 3).
  • Oublier l'attente après selectSensor() : la première lecture garde un peu du capteur précédent.
  • Diviser sans tester \(V_A \le V^+\) dans rsensor() : résistance négative ou division par zéro.
  • Mettre l'acquisition ou un Serial.print dans une interruption ; oublier volatile sur le drapeau.
  • Confondre la valeur d'alarme et la période : alarme = période / durée d'un pas (1 000 000 pas de 1 µs pour 1 s).
  • Remettre le watchdog à zéro dans une interruption : il ne voit plus un blocage de la boucle.
  • Confondre Harvard (deux mémoires) et RISC (jeu d'instructions réduit) : ce sont deux questions différentes, un PIC est les deux.
