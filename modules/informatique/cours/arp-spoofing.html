ARP spoofing ou empoisonnement du cache ARP

Le poste du laboratoire envoie ses résultats au serveur. Tout semble normal, mais chaque paquet passe d'abord par la machine d'un intrus branché sur le même switch. Le coupable : un protocole qui croit tout ce qu'on lui dit.

Fonctionnement normal du protocole ARP

Sur un réseau local, une machine connaît l'adresse IP de son destinataire, mais le switch achemine les trames grâce à l'adresse MAC. Le protocole ARP fait le lien entre les deux :

  1. ARP Request, en diffusion (broadcast, destination FF:FF:FF:FF:FF:FF) : A demande à tout le réseau « Qui est 192.168.1.1 ? ».
  2. ARP Reply, en unicast : D, qui a cette adresse, répond « Mon adresse MAC est 00:00:00:00:00:A0 ».
  3. A range la correspondance IP – MAC dans son cache ARP et s'en sert pour les trames suivantes.

Variantes ARP :

  • ARP Probe : quand une machine prend une nouvelle adresse, elle vérifie que personne ne l'utilise.
  • Gratuitous ARP : annonce envoyée sans qu'on l'ait demandée (sans état).
  • Reverse ARP : attribution d'adresse IP à partir de la MAC.
  • Proxy ARP : un mandataire répond à la place d'une autre machine (à désactiver sur les routeurs).

Déroulement de l'attaque

Dans un LAN commuté, le switch envoie normalement le trafic directement du port d'origine au port de destination : le hacker ne voit rien. Pour entendre le trafic, il mène une attaque de type homme du milieu (Man-in-the-Middle, MitM) en empoisonnant le cache ARP des victimes :

  • il envoie à PC A un gratuitous ARP : « 192.168.1.254 (le serveur B) est 00:00:00:00:00:03 », sa propre MAC ;
  • il envoie au serveur B : « 192.168.1.100 (PC A) est 00:00:00:00:00:03 » ;
  • les deux caches sont mis à jour sans vérification : A et B s'envoient leurs trames... au hacker, qui les relaie de façon transparente (le cours parle d'attaque APR).

La faiblesse vient d'ARP lui-même : aucune authentification, et une machine accepte une réponse qu'elle n'a pas demandée.

Mesures de protection

  • DHCP Snooping : le switch n'autorise les attributions d'adresses IP que si elles viennent d'un serveur DHCP légitime.
  • DAI (Dynamic ARP Inspection) : le switch intercepte et vérifie tous les paquets ARP, en les comparant à une base fiable (générée par le DHCP Snooping).
  • Segmenter le réseau avec des VLAN : on confine le trafic.
  • Entrées ARP statiques pour les équipements critiques : pour les serveurs sensibles ou la passerelle par défaut, on inscrit la correspondance IP – MAC « en dur ».

À retenir

  • ARP : request en broadcast « Qui est ... ? », reply en unicast avec la MAC, mémorisée dans le cache.
  • Attaque : faux gratuitous ARP vers les deux victimes, le hacker se met au milieu (MitM).
  • Protections : DHCP Snooping, DAI, VLAN, ARP statiques.
